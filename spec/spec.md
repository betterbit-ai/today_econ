# Feature: DIEM V2 경제·시사 릴스 발행 파이프라인

## Outcome

기존 오늘경제 파이프라인을 `DIEM — Daily Issue & Economy Magazine`으로
리브랜딩하고, 24시간 동안 경제와 시사 워크플로를 각각 4시간 간격으로
실행한다. 각 실행은 해당 분야의 현재 인기 뉴스가
핫뉴스 기준을 통과할 때 7초 릴스를 자동 발행한다. 마지막 Reel 발행 후
다음 정기 실행 전 24시간 공백이 예상되면 경제 워크플로가 품질 가드를
유지한 일일 최소 발행 후보를 추가로 평가하며, 릴스가 성공하면
동일 영상을 Instagram Story에도 독립적으로 발행한다.

독자는 원문을 모두 읽지 않아도 정확히 3문장 안에서 그날의 핵심 사실과
기사에 명시된 맥락을 이해할 수 있어야 한다. 운영자는 별도 데이터베이스나
상시 유료 인프라 없이 GitHub 기록만으로 선정 근거, 생성물, 권리 정보,
발행 상태와 실패 복구 과정을 추적할 수 있어야 한다.

## User and context

- 핵심 독자는 경제·시사 흐름을 챙길 시간이 부족한 20~30대 직장인,
  사회초년생, 재테크 초보자다.
- 운영자는 `DIEM Economy`와 `DIEM Issue` 두 GitHub Actions만으로 해당
  분야의 선별·준비·발행을 한 번에 실행하고, 자동 복구가 끝난 예외만
  직접 처리한다.
- 본 스펙은 기존 `@today.econ` 계정을 유지한 채 DIEM으로 전환하는
  V2 파이프라인을 정의한다.

## Required behavior

### 0. 채널 리브랜딩

1. 브랜드 표기는 `DIEM — Daily Issue & Economy Magazine`으로 통일한다.
   `DIEM`에는 “오늘을 놓치지 않는다”는 `carpe diem`의 연상을 담되,
   타 브랜드의 이름·로고·문구를 복제하지 않는다.
2. 기존 Instagram 계정의 우선 사용자 이름은 `@diem.magazine`, 실제
   변경 화면에서 사용할 수 없으면 `@diem_magazine`으로 한다.
3. 소개 문구는 다음 세 줄을 사용한다.

   ```text
   오늘을 놓치지 않는 경제·시사 브리핑
   지금 주목받는 경제·시사만 선별
   20·30 재테크 초보자를 위한 1분 매거진
   ```

4. 브랜드 해시태그는 `#diem`, `#diemmagazine`,
   `#데일리이슈앤이코노미`를 사용한다. 사용자 이름에 점이 포함되더라도
   해시태그에는 점을 사용하지 않는다.
5. 기존 게시물은 삭제·보관·소급 수정하지 않고 유지한다. 별도의 전환
   공지 게시물 없이 V2 발행을 시작한다.
6. Instagram의 이름·사용자 이름·소개 문구 변경은 운영자가 앱에서
   수동으로 수행한다. 파이프라인은 실제 적용된 사용자 이름을 설정값으로
   받아 댓글의 계정 멘션에 사용한다.
7. 프로필 이미지는 다음 조건을 만족하는 정사각형 PNG로 제작한다.
   - 짙은 네이비 배경 중앙에 흰색 `DIEM` 워드마크
   - `I` 또는 짧은 포인트 선에만 DIEM 블루 사용
   - 작은 원형 크롭에서 읽히는 안전 여백
   - 긴 영문 확장명과 기존 today.econ 로고는 제외

### 1. 주제 선정

#### 1.1 수집 범위와 인기 점수

1. 한국시간 기준 해당 날짜에 게시된 뉴스 중 네이버의 공개 현재 인기
   뉴스 목록을 최대 50위까지 수집한다. 실제 순위와 게시 시각을 안정적으로
   제공하는 다른 공개 공급자가 확보되면 동일한 정규화 규칙으로 확장할 수
   있으나, 단순 검색 결과를 인기 순위처럼 취급하지 않는다.
2. 각 공급자의 순위는 목록 크기를 `N`, 1부터 시작하는 순위를 `r`이라
   할 때 `100 - 99 × (r - 1) / (N - 1)`로 1~100점에 정규화한다.
   목록이 한 건이면 100점으로 처리한다.
3. URL 정규화, 정규화된 제목, 핵심 개체와 사건 서명을 이용해 동일
   기사 또는 동일 사건을 하나의 후보로 병합한다.
4. 둘 이상의 검증된 인기 공급자를 사용하게 되면 통합 인기 점수는 공급자별
   정규화 점수의 평균에 두 공급자 모두에 등장한 경우 10점을 더한 값으로
   한다. 임의의 AI 편집 점수로 인기 순서를 재정렬하지 않는다.
5. 네이버 인기 목록 수집이 실패하면 기존 언론사 RSS 후보와 실패 이유를
   `popularity_fallback`에 진단용으로 기록한다. RSS 배열 순서는 검증된 인기
   신호가 아니므로 핫뉴스 자동 발행에는 사용하지 않으며, “전국 최다 조회”처럼
   검증할 수 없는 표현도 쓰지 않는다.

#### 1.2 분야 규칙

1. 경제 분야에는 금리, 물가, 환율, 세금, 부동산, 대출, 예·적금,
   금융시장, 고용, 소득과 돈·일자리에 실질적인 영향을 주는 반도체,
   AI, 자동차, 유통 등 주요 산업 변화를 포함한다.
2. 단순 종목 추천, 근거 없는 전망, 일시적인 가격 등락, 일반 인사,
   단순 MOU와 홍보성 제품 기사는 경제 후보에서 제외한다.
3. 시사 분야에는 정책, 노동·고용, 주거, 교육, 인구, 복지, 사회 변화,
   국제 정세와 기술 규제를 포함한다.
4. 정치는 정책이나 생활 영향이 분명할 때만 포함한다. 정당 간 공방,
   자극적인 범죄·사고, 연예, 스포츠와 가십은 제외한다.
5. 한 후보가 두 분야에 모두 해당하면 핵심 사건의 직접 영향이 더 큰
   한 분야에만 배정한다. 같은 사건을 같은 한국 날짜에 다시 발행하지 않는다.
6. 해외의 한 개인에게 일어난 기이한 사건, SNS 화제, 단순 구조·이송,
   외모·분장·반응 중심의 인간 흥미 단신은 의료·교육 같은 분야 단어가
   포함돼도 시사 후보로 인정하지 않는다. 법·정책·제도 변화, 다수의
   안전·권리·생활에 미치는 영향 또는 한국 사회와의 명확한 연결이 원문에
   있어야 공익 시사 후보가 될 수 있다.

#### 1.3 7일 중복 방지

1. 모든 후보에 대해 다음 항목으로 간결한 `topic_signature`를 만든다.
   - 분야
   - 핵심 대상
   - 사건 또는 변화
   - 주요 인물·기업·정책명
2. 로컬 다국어 문장 임베딩으로 최근 7일간 모든 분야의 발행 기록과
   코사인 유사도를 비교한다.
3. 기본 임베딩 모델은
   `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`로
   하고 GitHub Actions 캐시를 사용한다.
4. 판정 기준은 다음과 같다.
   - `0.78 이상`: 자동 중복
   - `0.68 이상 0.78 미만`: 핵심 대상과 사건이 모두 겹칠 때 중복
   - `0.68 미만`: 새 주제
5. 모델 로딩 또는 추론 실패 시 정규화된 제목, 핵심 개체와 사건
   키워드의 결정적 중복 점수로 폴백하고 그 사실을 기록한다.
6. 같은 주제라도 새로운 최종 결정, 확정 수치, 판결, 금리 결정처럼
   결과를 실질적으로 바꾸는 후속 보도는 예외적으로 허용한다.
   `repeat_override: true`와 구체적인 이유가 필수이며 단순 논평이나
   추측은 예외로 인정하지 않는다.
7. 실제 자동 발행 전에 중복·비중복 한국어 기사 쌍 30~50개로 회귀
   데이터셋을 만들고 위 임계값의 기대 판정을 고정한다.
8. 형사소송법 개정처럼 제목의 관점만 바뀌는 같은 사건은 핵심 법안·
   정책·기업·결정의 표준 `event_key`로 먼저 중복 처리한다. 임베딩
   보조 프로세스는 JSON을 표준 입력으로 실제 전송했는지 회귀 테스트하고,
   실행 실패를 빈 유사도 결과로 처리하지 않는다.

#### 1.4 선정과 사실 검증

1. 통합 인기 순서대로 분야 적합성, 7일 중복, 원문 접근성, 게시 시각,
   출처, 이미지 확보 가능성을 검사하고 각 분야에서 가장 먼저 모든
   조건을 통과한 한 건을 선택한다.
2. 선정 원문 본문을 필수 근거로 사용하고 핵심 수치, 인물, 기업, 정책명과
   시행일을 구조화해 제목·본문의 모든 주장을 대조한다. 공식 자료나 별도의
   신뢰 가능한 기사가 후보군에 있으면 추가 검증 근거로 사용한다.
3. 추가 검증 자료는 가능하면 다른 도메인이며 단순 재전재가 아닌 독립
   출처여야 한다. 공식 발표 자료가 있으면 이를 우선한다. 추가 자료의 부재
   자체만으로 현재 인기 원문을 탈락시키지는 않는다.
4. 원문 내부가 모순되거나 확보된 근거가 충돌하거나 핵심 사실을 원문에서
   확인할 수 없으면 다음 순위 후보로 넘어간다.
5. 후보가 선정된 뒤 제목·본문 LLM 생성 또는 검증이 실패하면, 해당
   후보를 발행하지 않고 탈락 이유를 기록한 뒤 같은 분야의 다음 인기
   후보를 다시 평가하고 준비한다.
6. 해당 날짜의 모든 후보가 품질 기준을 통과하지 못하면 품질이 낮은
   기사나 전날 기사로 채우지 않는다. 해당 분야를 `no_publish`로
   기록하고 다른 분야는 독립적으로 계속한다.
7. 기사 제목·요약·본문 도입부에서 핵심 주체와 사건을 하나의
   `news_frame`으로 고정한다. 본문 뒤쪽의 인물 이력, 과거 IPO, AI 투자
   같은 부수 언급으로 주요 사건을 바꾸지 않는다.
8. `10배 이상` 증감, 증시·종목의 `15% 이상` 등락, `세계 1위`·
   `사상 최대`처럼 실패 시 신뢰 손상이 큰 주장은 다른 언론사나 공식
   자료의 독립 근거가 같은 수치·사건을 확인할 때만 통과시킨다. 근거가
   없으면 현재 기사를 폴백으로 요약하지 않고 다음 인기 후보를 전체
   파이프라인에 태운다.

#### 1.5 핫뉴스와 실행 시점

1. 자동 실행은 현재 네이버 인기 순위, 기사 게시 시각, 기존 편집 가치
   점수를 결합해 핫뉴스 여부를 판정한다. 네이버가 공개하지 않는 절대
   조회수는 추정하거나 기록하지 않는다.
2. 일반 후보의 핫 점수는 인기 점수 55%, 신선도 30%, 편집 가치 15%로
   계산한다. 인기 점수 70 이상, 게시 후 12시간 이내, 종합 70점 이상을
   모두 만족해야 한다.
3. 사이드카·서킷브레이커·거래정지·긴급 정책 결정처럼 시점 민감성이
   명확한 후보는 긴급 보너스 최대 10점을 적용한다. 이 경우 인기 점수
   50 이상, 게시 후 6시간 이내, 종합 65점 이상을 요구한다.
   사람의 병원 긴급 이송, 기사 제목의 일반적인 `긴급`·`비상`·`속보`
   표현만으로는 긴급 뉴스로 판정하지 않는다.
4. 기사 게시 시각을 파싱하지 못한 후보는 현재 랭킹 관측 시각을 신선도
   대체 근거로 쓰되 인기 점수 90 이상과 편집 가치 60 이상을 모두
   만족해야 한다. 이 폴백 사용 사실을 원장에 기록한다.
5. 같은 한국 날짜에 이미 발행한 사건과 중복으로 판정된 후보는 새로운
   확정 수치나 후속 결정이 있어도 재발행하지 않는다. 다음 날 이후에는
   기존 7일 중복 규칙의 의미 있는 후속 보도 예외를 적용할 수 있다.
6. 핫뉴스 기준을 통과한 후보가 없으면 정상적인 `no_publish` 관측으로
   기록하고 Instagram에는 아무것도 발행하지 않는다.
7. 마지막 성공 Reel 이후 20시간 이상 지났거나 성공 기록이 없으면 다음
   4시간 예약 실행 전에 24시간 공백이 생길 수 있으므로 `DIEM Economy`가
   일일 최소 발행 모드로 후보를 다시 평가한다. 이 모드는 검증된 인기
   신호가 있는 게시 후 24시간 이내 기사 중 인기 점수 50 이상, 편집 가치
   70 이상, 종합 점수 55 이상을 요구한다. 게시 시각이 없으면 관측 후
   4시간 이내, 인기 점수 80 이상과 편집 가치 70 이상을 모두 요구한다.
8. 일일 최소 발행 모드는 신선도·인기 임계값만 제한적으로 완화한다.
   분야 적합성, 원문 접근성, 사실·수치 검증, 7일 중복, 생성물 검증,
   이미지 권리와 의미 일치 기준은 일반 자동 발행과 동일하다. 안전한
   후보가 없으면 낮은 품질이나 24시간을 넘긴 기사로 강제 발행하지 않는다.
9. 시간대가 없는 `YYYY-MM-DD HH:mm:ss` 형식의 국내 언론사 게시 시각은
   Asia/Seoul로 해석한다. 게시 시각이 관측 시각이나 현재 시각보다 미래인
   경우 신선도를 0시간으로 고정하지 않고 잘못된 시각으로 기록한 뒤 검증된
   관측 시각 폴백을 적용한다.

### 2. 타이틀과 표지

1. 타이틀은 공백을 포함한 가시적 grapheme 기준 총 14자 이하며 정확히
   두 줄이다. 줄바꿈 문자는 글자 수에서 제외하고 각 줄은 4~7자를
   권장한다.
2. 첫 줄은 DIEM 블루, 둘째 줄은 화이트로 표시한다.
3. 생성 모델은 기사 근거 안에서 후보 5개를 만들고 다음 우선순위로
   하나를 선택한다.
   - 사실 정확성
   - 길이와 2줄 형식
   - 즉시 이해되는 핵심 사건
   - 원문을 읽고 싶게 하는 호기심
4. 핵심 사실을 숨기는 “모르면 손해”, “결국 터졌다”, “대체 왜?” 같은
   낚시 표현, 불필요한 따옴표·문장부호와 사실 왜곡은 금지한다.
5. 검증된 수치가 사건의 핵심이면 수치를 사용할 수 있으나, 숫자만
   강조해 맥락을 왜곡해서는 안 된다.
6. 표지 메타는 한국시간 발행일 기준으로 정확히 다음 중 하나를 쓴다.
   - `YYYY.MM.DD · ECONOMY`
   - `YYYY.MM.DD · ISSUE`
7. 표지는 1080×1920이며 단일 DIEM 디자인 시스템을 사용한다.
   - 배경: `#080C16`
   - 블루: `#4D7CFE`
   - 화이트: `#F7F9FC`
   - 보조색: `#A6AEC1`
   - 서체: Pretendard
   - 타이틀: ExtraBold와 좁은 자간
   - 날짜·분야: Medium과 넓은 자간
8. 사진 위에 어두운 그라데이션을 적용하고 텍스트 안전 영역을 확보한다.
   기존 Obsidian·Ivory·Cyber 테마는 V2 표지에서 사용하지 않는다.
9. 경쟁 구도, 선두·추격, 흑자·적자 전환처럼 방향이 핵심인 기사에서는
   누가 앞서고 뒤처지는지와 변화 전후 상태를 구조화해 검증한다. 제목이
   원문의 방향을 뒤집거나 `중국 추격`처럼 추격 주체가 모호하면 다음 제목
   후보를 사용하고, 모두 실패하면 해당 기사 발행을 중단한다.
10. `절망 시대`, `완전 통과`, `대박`, `환호 터졌다`, `기대↑`처럼
    과장·감정·기계적 축약은 코드로 탈락시킨다. 제목은 `news_frame`의
    핵심 주체와 사건을 모두 쓰고, 부수 언급을 제2의 주제로 붙이지 않는다.

### 3. 웹 이미지 선정

1. 이미지 출처 허용 목록은 다음과 같다.
   - Pexels 우선
   - Unsplash 차순위
   - 라이선스가 기계 판독 가능하며 Public Domain, CC0, CC BY 또는
     프로젝트와 양립 가능한 조건임을 확인한 Wikimedia Commons
   - 재사용 허가가 명시된 공공기관·정부·기업 보도 자료
2. 일반 검색 결과, 뉴스 기사에 삽입된 사진, 워터마크가 있는 이미지와
   재사용 권한을 확인할 수 없는 이미지는 사용하지 않는다.
3. 핵심 대상, 사건과 분야로 3~5개의 검색어를 만들고 최대 20개 후보를
   수집한다.
4. 라이선스, 최소 해상도, 세로 크롭 가능성, 깨진 URL, 워터마크를 먼저
   검사한 뒤 다음 요소로 점수를 계산한다.
   - 주제·타이틀과의 의미 일치도
   - 9:16 크롭에서 핵심 피사체와 텍스트 안전 영역 보존
   - 타이틀 가독성을 해치지 않는 시각적 단순성
5. 선택 신뢰도가 기준 미만이면 다음 순서로 폴백한다.
   - 핵심 대상의 직접 사진
   - 사건을 설명하는 개념 사진
   - 최근 7일 동안 쓰지 않은 사전 검수 분야 이미지
   - 사진 없이 DIEM 타이포그래피만 사용하는 표지
6. 원본 URL, 제작자, 서비스, 라이선스, 검색어, 조회 시각, 점수와 선택
   이유를 발행 기록에 남긴다.
7. 검색어는 기사 핵심 대상과 사건을 먼저 사용한다. `정부`, `정책`,
   `국회`처럼 범용적인 단어만으로 된 검색어와 일반 의회 내부 사진은
   기사 자체가 국회 공간을 다루는 경우가 아니면 직접 사진 후보로
   인정하지 않는다.
8. 해상도·세로 비율만으로 의미 일치 기준을 통과할 수 없으며, 이미지
   설명과 구체 검색어 사이에 최소 한 개 이상의 의미 토큰 일치가 있어야
   한다. 같은 품질이면 무작위 선택 대신 점수가 가장 높은 미사용 사진을
   선택한다.
9. 최근 7일 발행 이미지의 공급자 ID, 정규화 URL과 파일 SHA-256 중
   하나라도 일치하면 해당 이미지를 제외한다. 다운로드 후 파일 해시가
   뒤늦게 중복으로 확인되면 다음 후보를 다시 고르고, 미사용 사진이
   없으면 타이포그래피 표지로 폴백한다.
10. `정부`, `정책`, `지원` 같은 범용 검색어의 일치만으로 사진을 채택하지
    않는다. 검색어에서 범용 토큰을 제외한 기사 핵심 대상 토큰이 공급자
    설명·태그에 최소 하나 이상 일치해야 한다. 부적합 후보와 사유를 실행
    기록에 남기고 같은 검색 결과의 다음 사진, 다음 검색어, 다음 공급자
    순서로 자동 재선정하며, 모두 실패하면 타이포그래피 표지로 폴백한다.
11. 사람·직업·연령·사건 역할이 기사 핵심인 경우 사진 설명과 태그가 그
    역할까지 일치해야 한다. 학생·미성년자·환자를 다룬 기사에 성인 의사,
    교사나 무관한 모델 사진을 대신 쓰지 않는다. 실제 인물 사진의 권리와
    동일성을 확인할 수 없거나 역할이 충돌하면 무사진 표지를 선택한다.
12. 이미지 의미 점수는 한국어 기사 제목을 영어 검색 토큰의 분모에 섞어
    희석하지 않는다. 검색어 적합도와 기사 시각 역할 적합도를 각각 평가한
    뒤 둘 다 기준을 통과해야 한다.
13. 무사진 폴백은 빈 단색 배경이 아니라 DIEM 디자인 시스템 안에서 분야별
    추상 도형·패턴과 워드마크를 사용한 의도적인 에디토리얼 표지여야 한다.
14. 인물 연령·직업·환자 역할은 제목과 요약에서 주제일 때만 사진
    필수 역할로 삼고, 본문 뒤쪽의 인물 이력으로 오인하지 않는다. 한국 국회·
    청와대·대통령실 기사에는 한국 장소 메타데이터가 있는 사진만 쓰며,
    영국 의회 등 다른 국가의 기관 사진은 자동 탈락시킨다.

### 4. 본문·댓글·해시태그

#### 4.1 본문

1. NFC 정규화 후 정확히 3개의 한국어 문장으로 구성한다.
2. 각 문장은 공백, 문장부호와 이모지를 포함한 가시적 grapheme 기준
   최대 120자이며 문장 내부 줄바꿈은 없다.
3. 문장 사이는 빈 줄 하나, 즉 `\n\n`으로 구분한다. URL과 해시태그는
   본문에 넣지 않는다.
4. 문장 역할은 다음과 같다.
   - 1문장: 무슨 일이 일어났는지
   - 2문장: 핵심 수치·사실·맥락
   - 3문장: 기사나 교차 검증 근거에 명시된 배경·전망·의미. 명시된
     내용이 없으면 다음으로 중요한 사실
5. 기사에 없는 투자 조언, 생활 영향, 전망이나 인사이트를 만들지 않는다.
6. 1문장 끝에는 내용에 맞는 이모지 정확히 1개, 2문장에는 이모지 0개,
   3문장 끝에는 내용에 맞는 이모지 정확히 1개를 둔다.
7. 두 이모지는 달라도 되며 같은 이모지가 가장 적합할 때만 중복한다.
   사실이나 감정을 과장하는 이모지는 금지하고, 정치·재난·참사에는
   가벼운 이모지를 사용하지 않는다. 폴백은 경제 `📊`, 시사 `📰`다.
   OBMC를 연상시키는 `🍏`을 기본값으로 사용하지 않는다.
8. 수치 문장은 원문의 비교 기준과 단위를 함께 보존한다. `전기 대비
   연율 1.5%`를 `전년 대비 1.5%`로 바꾸거나 비교 기준을 생략하면
   제생성을 시도하고, 모두 실패하면 다음 기사 후보로 넘어간다.
9. 1문장은 `news_frame`의 핵심 주체와 사건을 모두 포함해야 하며,
   과거 IPO·부수 AI 언급 등 현재 사건과 다른 키워드를 3문장 요약의
   별도 주제로 확장하지 않는다.

#### 4.2 댓글 체인

1. 릴스 발행 후 첫 댓글은 1문장 끝에 사용한 이모지 하나만 포함한다.
2. 첫 댓글의 대댓글은 실제 계정 사용자 이름 멘션과 12~15개 해시태그로
   구성하며 중복, 점과 공백이 포함된 해시태그를 금지한다.
3. 해시태그 구성은 총 15개 이내에서 다음 범위를 따른다.
   - 분야 기본 태그 3개
   - 독자·형식 태그 2~3개
   - DIEM 브랜드 태그 3개
   - 기사에 실제 등장하는 주제·기업·인물 태그 4~6개
4. 태그 수 때문에 Instagram API가 거절한 것이 확인되면 핵심 태그
   5개로 한 번만 재시도한다. 원래 목록과 축소 목록을 모두 기록한다.
5. 릴스, 첫 댓글과 대댓글은 독립된 상태로 관리한다. 댓글 실패 때문에
   이미 발행된 릴스를 삭제하거나 다시 올리지 않는다.
6. 댓글 단계는 같은 Instagram 미디어·댓글 ID에만 최대 3회 재시도한다.
   성공한 단계는 다시 실행하지 않으며 3회 실패 후
   `manual_action_required`로 전환한다.
7. 구현 전 Instagram 전문 계정과 액세스 토큰에 댓글 관리 권한이
   있는지 확인한다. 권한이 없으면 릴스 발행은 계속하고 댓글 단계만
   `manual_action_required`로 기록한다.

### 5. 릴스·음악·발행

#### 5.1 릴스 구성

1. 릴스 한 편은 표지 이미지 한 장으로 만든 1080×1920, 7초 영상이다.
2. 영상에는 날짜·분야와 두 줄 타이틀만 표시하고 3문장 본문, 추가
   슬라이드, 차트와 액션 카드를 넣지 않는다.
3. 표지는 정적 영상을 기본으로 한다. 움직임을 적용할 경우 배경 사진에만
   제한하고 날짜·분야·타이틀·브랜드 텍스트는 고정해 글자가 흔들리거나
   리샘플링되어 보이지 않게 한다.
4. 출력은 Instagram 수집에 적합한 H.264, 30fps, `yuv420p`, fast-start
   MP4와 AAC 오디오를 사용한다.

#### 5.2 음악

1. 초기 V2에는 직접 제작한 DIEM 오리지널 무보컬 음원 6곡을 둔다.
   - 경제용: 안정적인 비트, 밝은 미니멀, 테크 펄스 각 1곡
   - 시사용: 중립 뉴스룸, 차분한 다큐멘터리, 절제된 리듬 각 1곡
2. 음원은 7초 루프에 맞추고 낮은 음량과 짧은 시작·종료 페이드를
   적용한다.
3. 같은 분야의 직전 사용곡은 제외하고 최근 사용 횟수가 가장 적으며
   주제 분위기에 맞는 곡을 선택한다.
4. 재난·참사 등 음악이 부적절한 주제는 무음으로 발행한다.
5. 곡 ID, 분류, 선택 이유, 라이선스 선언과 SHA-256을 GitHub에 기록한다.
6. 선택 음원 합성 실패 시 같은 분야의 다른 곡으로 한 번 재시도하고,
   다시 실패하면 릴스 발행을 막지 않고 무음으로 출력한다.
7. 기존의 단순 3음 사인파, Instagram 유행 음원의 API 자동 선택과
   라이선스가 불명확한 외부 음원은 사용하지 않는다.

#### 5.3 일정과 독립 실행

1. 자동 실행은 24시간 동안 4시간마다 경제와 시사 워크플로를 각각
   실행한다. GitHub Actions cron은 UTC `0 */4 * * *`를 사용하며 이는
   한국시간 01:00, 05:00, 09:00, 13:00, 17:00, 21:00이다.
2. `DIEM Economy`는 경제 후보만, `DIEM Issue`는 시사 후보만 새로
   평가한다. 수동 실행도 별도 phase 입력 없이 선택한 분야를 선별하고
   준비한 뒤 실제 Instagram 발행까지 진행한다.
3. 각 실행은 이전 실행의 미완료 릴스·Story·댓글 단계가 있으면 새 후보보다
   먼저 멱등 복구한다. 완료 또는 `no_publish` 관측은 같은 날 원장의
   이력으로 보존한 뒤 새 실행 슬롯을 만든다.
4. 두 분야와 릴스·Story·댓글 단계는 독립 상태와 재시도를 가진다. 경제
   실패가 시사 발행을 막거나 그 반대가 되어서는 안 된다.
5. 릴스 생성·업로드는 재시도하되 Carousel로 폴백하지 않는다. Story는
   릴스의 대체 형식이 아니라 릴스 성공 후 동일 7초 영상을 게시하는 독립
   배포 단계다. Story 실패는 이미 성공한 릴스나 댓글 상태를 되돌리거나
   릴스를 중복 게시하지 않는다.
6. 각 건은 날짜·분야·실행 슬롯으로 결정되는 안정적인
   `publication_key`를 가지며 발행 전 GitHub 상태와 Instagram의 최근
   게시물을 조정해 중복 발행을 방지한다.
7. Story는 성공한 릴스와 동일한 임시 공개 `video_url`을 사용하며 최대
   3개 실행에 걸쳐 재시도한다. 성공한 Story는 다시 만들지 않고, 3회 실패
   또는 Business 계정·권한 조건 미충족은 `manual_action_required`로
   기록한다. 미완료 Story 복구를 새 기사 선정보다 먼저 시도한다.

### 6. GitHub 기록과 상태 모델

1. 별도 데이터베이스 없이 다음 자료를 Git에 영구 보관한다.
   - 일일 후보와 순위·탈락 이유
   - 선정 기사와 교차 검증 URL·확인 시각
   - 주제 서명·유사도·중복 판정과 예외 사유
   - 제목 후보와 최종 선택 이유
   - 본문·이모지·댓글·해시태그
   - 이미지 출처·라이선스·점수
   - 음원 ID·권리 정보·파일 해시
   - 단계별 상태·시도 횟수·오류·Instagram ID와 링크
2. 일일 원장은 `data/publications/YYYY/MM/YYYY-MM-DD.json`에 경제와
   시사의 현재 실행 항목과 같은 날 완료된 실행 이력을 함께 저장한다.
   기존 schema v2 원장은 읽을 수 있어야 하며 새 반복 발행 원장은
   schema v3로 점진 전환한다.
3. 7일 중복과 음원 순환을 위한 작은 파생 인덱스는
   `data/editorial-history.json`에 저장한다. 원장은 진실의 원본이고
   인덱스는 원장에서 다시 만들 수 있어야 한다.
4. 상태는 최소 `planned`, `generating`, `ready`, `publishing`,
   `published`, `no_publish`, `retry_pending`, `failed`,
   `manual_action_required`를 사용한다. 릴스, Story, 첫 댓글과 대댓글은 각각
   자신의 상태·시도 횟수·외부 ID를 가진다.
5. 같은 브랜치의 발행 작업은 GitHub Actions concurrency group으로
   직렬화하고 진행 중 작업을 취소하지 않는다. 상태 커밋 전에는 원격
   변경을 다시 읽고 충돌을 조정한다.
6. 발행 전 `ready` 상태를 커밋하고 발행 후 외부 ID와 결과를 다시
   커밋한다. 발행 후 커밋이 실패한 경우 다음 실행은 최근 Instagram
   게시물의 날짜·분야·정확한 본문을 대조해 기존 게시물을 복구한 뒤
   새 게시 여부를 결정한다.
7. 원본 이미지와 최종 MP4는 Instagram 수집을 위해 GitHub 임시
   Release에 올리고 최대 72시간 뒤 삭제한다. 대용량 미디어를 Git
   이력에 영구 누적하지 않는다.
8. 임시 미디어가 삭제돼도 모든 텍스트, 출처, 권리 정보, 선택 점수,
   외부 게시물 ID와 최종 파일 해시는 영구 기록한다.

### 7. 생성 모델과 폴백

1. Groq 무료 티어를 유지하며 기본 생성 모델은
   `openai/gpt-oss-120b`, 폴백은 `openai/gpt-oss-20b`로 한다.
2. 모델 식별자는 중앙 설정값으로 관리하고 응답 기록에는 실제 사용
   모델을 남긴다.
3. LLM은 제목 후보와 기사 근거 기반 3문장 초안에만 사용한다. 인기
   순위, 중복 임계값, 길이, 줄 수, 이모지와 해시태그 형식은 코드가
   결정적으로 검증한다.
4. 429 응답에서는 `retry-after`를 우선 사용한다. 무료 한도 초과를
   유료 호출로 자동 전환하지 않는다.
5. 모든 생성 모델 호출이 실패하거나 모델 결과가 형식·사실 검증을
   통과하지 못하면 규칙 기반 원고를 자동 발행하지 않는다. 해당 후보를
   `editorial_generation_failed`로 기록하고 같은 분야의 다음 인기 후보를
   다시 평가한다. 후보가 모두 소진되면 `no_publish`로 닫는다.
6. 규칙 기반 원고 조립 함수는 회귀 테스트와 수동 진단용으로만 유지하며,
   자동 발행 경로의 최종 폴백으로 사용하지 않는다.

### 8. 알림과 운영

1. GitHub의 일일 원장, 커밋과 Issue를 상태의 원본으로 사용한다.
2. Slack은 콘텐츠 전달이 아닌 사람에게 필요한 상태 변화 알림에만
   사용한다.
3. Slack 알림은 다음 이벤트만 보낸다.
   - 발행 완료: 분야, 제목과 Instagram 링크
   - 최초 실패와 재시도 예정: 실패 단계, 시도 횟수와 다음 처리
   - 재시도 복구 성공
   - 최종 실패와 수동 조치 필요: GitHub Issue·Actions 링크
   - 마지막 성공 Reel 이후 24시간 이상 무발행: 마지막 발행 시각,
     무발행 시간과 후보 탈락 사유 집계를 Slack으로 전달
4. 짧은 자동 재시도마다 중복 알림을 보내지 않고 상태가 바뀔 때만
   보낸다. 본문 전문, 이미지와 영상 파일은 Slack으로 전송하지 않는다.
5. `manual_action_required`와 비정상 최종 실패는 중복 방지 키를 가진
   GitHub Issue를 생성한다. 같은 발행 건의 반복 오류는 기존 Issue에
   누적하고 복구되면 자동으로 닫는다. 24시간 이내의 정상 핫뉴스
   `no_publish` 관측은 원장에만 남긴다. 24시간 이상 무발행 상태에서
   일일 최소 발행 후보까지 소진되면 해당 실행의 새 `publication_key`에
   Slack 알림을 남기고, 같은 무발행 기간에는 최대 24시간에 한 번만 다시
   알린다. 이 관측은 운영 장애가 아니므로 GitHub Issue는 만들지 않는다.

## Constraints

- 모든 한글 텍스트 입력과 저장 전에 NFC 정규화를 적용한다.
- 별도 데이터베이스, 상시 서버와 상시 유료 인프라를 도입하지 않는다.
- Groq 무료 티어, GitHub Actions·커밋·Issues·임시 Releases와 기존
  Instagram·Slack 연결을 사용한다.
- 새 런타임 의존성은 로컬 다국어 임베딩과 이미지 의미 일치도 검증에
  필요한 최소 범위로 제한하며 버전과 모델 ID를 고정하고 캐시한다.
- 외부 이미지·음원은 상업적 사용과 필요한 재배포 권리가 확인된 경우만
  사용한다. 권리가 불명확하면 무사진 또는 무음으로 폴백한다.
- Instagram은 전문 계정이어야 하며 콘텐츠 발행과 댓글 관리 권한을
  구분해 사전 점검한다.
- 예약 실행 지연이 발생해도 일일 기준일과 표지 날짜는 Asia/Seoul
  시간대로 계산한다.
- 외부 포털 HTML과 Meta·Groq API는 변경될 수 있으므로 파서 계약,
  상태 코드와 폴백 경로를 테스트 가능하게 격리한다.
- 기존 사용자 변경사항과 V1 데이터는 덮어쓰지 않는다.

## Risks and rollback

- **포털 구조 변경:** 네이버 HTML 변경으로 인기 목록 수집이 중단될 수
  있다. 어댑터와 fixture를 격리하고 기존 언론사 RSS로 폴백한다.
- **기사·이미지 권리:** 원문 접근 제한이나 이미지 라이선스 변경이
  발생할 수 있다. 권리·근거를 실행 시점에 기록하고 불명확하면 후보
  제외 또는 무사진 표지를 사용한다.
- **모델·무료 한도:** Groq 모델 또는 무료 한도가 변경될 수 있다.
  중앙 모델 설정과 규칙 기반 폴백으로 발행을 유지하며 유료 전환은
  별도 결정 없이는 금지한다.
- **Meta 권한:** 댓글 권한 미승인이나 토큰 만료가 발생할 수 있다.
  릴스와 댓글 상태를 분리하고 GitHub Issue·Slack으로 수동 조치를
  알린다.
- **외부 발행 후 상태 커밋 실패:** Instagram 발행 직후 Git 커밋이
  실패하면 중복 위험이 남는다. 재실행 전에 최근 미디어의 날짜·분야와
  정확한 본문을 대조하며 불확실하면 자동 재발행하지 않고 수동 조치로
  전환한다.
- **Git 충돌:** 수동·예약 실행이 겹칠 수 있다. concurrency group과
  원격 상태 재조회로 직렬화하고 서로 다른 분야의 상태를 덮어쓰지 않는다.
- **과도한 발행:** 랭킹 상위의 서로 다른 기사가 연속으로 등장할 수 있다.
  핫 점수·게시 시각·당일 강제 중복 방지로 발행을 제한하고, 운영 데이터가
  쌓이면 최소 간격이나 일일 상한을 별도 결정으로 추가한다.
- **계정명 롤백:** Instagram 사용자 이름 변경은 이전 이름을 즉시 다시
  확보할 수 있다는 보장이 없다. V2 dry-run과 프로필 자산 검수를 마친
  뒤 실제 계정을 변경한다.
- **코드 롤백:** V1 경로와 데이터 파일을 V2 안정화 전까지 보존하고
  `PIPELINE_VERSION` 또는 동등한 명시적 전환 설정으로 한 버전만
  예약 발행한다. 문제가 생기면 V2 예약을 끄고 V1 워크플로로 되돌린다.
  V2 일일 원장은 삭제하지 않아 감사 기록으로 남긴다.
- **콘텐츠 롤백:** 잘못 발행된 게시물의 자동 삭제는 하지 않는다.
  운영자가 사실관계를 검토해 Instagram에서 수정·보관·삭제를 결정하고
  GitHub 원장에 조치 결과를 기록한다.
