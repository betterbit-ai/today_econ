# Feature: DIEM 성과 학습 루프와 편집 복구력 강화

## Outcome

DIEM의 과거·신규 Reel 성과를 같은 관찰 구간끼리 비교해 잘된 패턴과
부진한 패턴을 GitHub 리포트로 누적하고, 충분한 표본에서만 다음 기사 선정에
작은 가중치로 반영한다. 동시에 좋은 기사가 표지 제목 생성 실패만으로
버려지지 않게 제한된 LLM 제목 재정제 단계를 두고, 맥락 사진 검색 범위를
권리 확인 가능한 무료 소스로 확장한다.

## Required behavior

### 1. 반복 가능한 성과 분석

1. 발행 원장의 `24h`, `72h`, `7d` Instagram 지표를 서로 섞지 않고 분석한다.
   목표 관찰 시각보다 허용 오차를 넘겨 수집된 늦은 백필은 원장에
   보존하되 성과 비교와 선정 prior 표본에서 제외한다.
2. 카테고리별 조회·도달 중앙값, 공유율, 저장률, 참여율, 평균 시청 시간과
   계정 팔로워 증분 추정치를 기록한다. 누락 지표는 0으로 취급하지 않는다.
3. 표본이 5편 미만이면 승자·부진 패턴을 확정하지 않는다. 충분한 표본에서
   상위·하위 성과와 제목·주제·이미지·음악 특성의 lift를 계산한다.
4. 결과를 `data/reports/diem-performance.json`과 Markdown에 원자적으로 저장한다.
5. 이후 기사 선정에는 충분한 표본으로 검증된 주제 특성만 제한된 범위로
   가감한다. 품질·정확성·중복·시의성 게이트를 우회하지 않는다.
6. 프로젝트 전용 Codex skill과 운영 플레이북을 저장해 같은 분석을 반복할
   수 있게 한다.

### 2. 제목만 실패한 편집 결과 복구

1. 원문 제목 길이는 발행 실패 사유가 아니다. LLM의 캡션·사실 정렬은
   유효하지만 제목 후보만 실패한 경우, 같은 모델에 제목 JSON만 한 번
   재요청한다.
2. 재요청은 고정된 기사 프레임과 사실, 기존 캡션을 바꾸지 않으며 정확히
   2줄·합계 14자·주체와 사건·확정 상태를 지키게 한다.
3. 제목 재정제가 실패하면 다음 모델을 시도하고, 모든 모델이 실패하면 기존
   결정대로 같은 분야의 다음 기사 후보를 전체 파이프라인에 태운다.
4. 결정론적 저품질 제목·본문 폴백은 자동 발행에 사용하지 않는다.
5. 모델별 원본 실패, 제목 재정제 시도와 최종 실패 사유를 원장에 보존하고
   Slack `no_publish` 알림에서 가장 유용한 이유를 보여 준다.

### 3. 이미지 맥락과 공급원 확대

1. 기존 Pexels·Unsplash·Wikimedia에 Openverse의 상업 이용·수정 허용
   이미지를 추가한다. CC0, Public Domain, CC BY, CC BY-SA만 허용한다.
2. 부동산 거래, 현금·지역 지원, 노동 현장 등 반복 실패 주제에 구체적인
   사물·장소 중심 영문 검색어를 우선한다.
3. 기존 무관 인물 차단, 실제 인물 최후 단계 사용, 맥락 적합성, 권리,
   해상도와 최근 7일 이미지 중복 금지 조건은 유지한다.
4. 모든 공급원·검색어·탈락 사유와 최종 폴백 사유를 원장에 기록한다.

### 4. 음악 판단

1. 현 음원 수를 즉시 늘리지 않는다. 성과 리포트에 트랙·무드 사용 분포와
   특정 트랙 편중 경고를 추가한다.
2. 한 트랙이 비민감 Reel의 20%를 넘거나, 충분한 표본에서 반복 피로가
   관측될 때만 새 음원 추가를 제안한다.

## Acceptance criteria

- [ ] 성과가 없는 저장소에서도 리포트가 `insufficient_data`로 안전하게 생성된다.
- [ ] 관찰 구간과 카테고리별 중앙값·비율·누락·표본 수가 기록된다.
- [ ] 충분한 표본이 없으면 성과 가중치가 0이며, 있더라도 상한을 넘지 않는다.
- [ ] 긴 원문 제목 사례에서 유효 캡션을 유지한 채 제목 전용 재정제가 성공한다.
- [ ] 제목 재정제까지 실패하면 상세 모델 시도가 원장에 남고 다음 후보로 이동한다.
- [ ] Openverse 허용 라이선스만 후보로 들어오며 무관 인물·최근 중복 게이트를 통과해야 한다.
- [ ] 수동 `collect_insights` 작업으로 발행 없이 성과 수집과 리포트 갱신이 가능하다.
- [ ] 전용 skill과 Markdown 플레이북이 저장되고 skill 검증을 통과한다.
- [ ] `npm run test`와 `git diff --check`가 통과한다.

## Constraints

- 별도 DB, 상시 유료 서버, 신규 유료 이미지·분석 서비스를 추가하지 않는다.
- GitHub 원장과 Actions, 기존 Instagram Graph API와 Slack을 사용한다.
- 한 건의 바이럴이나 부진 Reel로 주제를 금지하거나 자동 전략을 확정하지 않는다.
- 기사 사실성, 제목 확정 상태, 저작권, 무관 인물 차단과 7일 중복 금지를
  성과 가중치보다 항상 우선한다.
- 음악 파일은 이번 범위에서 추가하지 않는다.

## Verification

- 제목 전용 재정제 성공·실패·다음 후보 전환 단위 테스트
- 상세 편집 실패 진단 원장 보존 테스트
- 성과 리포트의 관찰 구간 분리, 중앙값, 표본 하한과 가중치 상한 테스트
- Openverse 라이선스 정규화·차단·선정 테스트
- GitHub Actions 수동 성과 수집 경로 정적 테스트
- skill quick validation
- `node .codex-harness/scripts/verify-project.mjs`

## Out of scope

- Instagram 게시물 삭제·재발행
- 유료 광고, 브랜드 영업, Gifts 또는 구독 기능
- 기사 원문·언론사 사진의 권리 확인 없는 재사용
- 표본 미달 상태의 자동 주제 블랙리스트
- 신규 음원 다운로드·라이선스 검수

## Risks and rollback

- 성과 API 지표가 비어 있으면 리포트만 `insufficient_data`로 유지하고 선정
  점수에는 반영하지 않는다.
- 제목 재정제가 rate limit을 악화시키면 한 번의 제한된 호출을 비활성화해
  기존 다음 후보 전환으로 돌아간다.
- Openverse 메타데이터가 불충분하면 후보가 기존 적합성 게이트에서 탈락하고
  기존 공급원 또는 중복되지 않는 프로젝트 원본 타이포그래피로 돌아간다.
- 성과 가중치가 품질을 낮추면 리포트 생성은 유지하고 선정 prior만 0으로
  비활성화한다.
