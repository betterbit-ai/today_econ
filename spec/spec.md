# Feature: DIEM 1개월 품질 안정화·브랜드 협업 준비 실험

## Outcome

DIEM은 당장 광고 영업이나 플랫폼 Gifts 수익화를 시작하지 않는다. 먼저
4주 동안 현재 핫뉴스의 편집 품질과 성과 측정 기반을 안정화하고, 브랜드가
포트폴리오로 평가할 수 있는 승인형 `DIEM 기초` 콘텐츠를 주 1편씩 총
4편 발행한다.

`DIEM 기초`는 자동 발행하지 않는다. GitHub Actions가 초안과 미리보기를
준비해 GitHub에 기록하고 Slack으로 검토 링크를 보낸 뒤, 운영자가 명시한
발행 ID만 별도의 수동 `workflow_dispatch`로 Instagram에 발행한다. 4주가
끝나면 핫뉴스와 `DIEM 기초`의 품질 및 성과를 비교해 다음 단계의 유지,
수정 또는 중단을 결정한다.

## User and context

- 핵심 독자는 경제·시사 원문을 모두 읽을 시간이 부족한 20~30대 직장인,
  사회초년생과 재테크 초보자다.
- 운영자는 최근 콘텐츠의 제목, 본문과 사진 품질이 브랜드 포트폴리오로
  쓰기에는 충분하지 않다고 판단했다.
- 운영자는 콘텐츠 품질이 검증되기 전 한 달 동안 브랜드 아웃바운드,
  광고 안내 게시물과 공개 미디어킷을 원하지 않는다.
- 향후 첫 협업 후보는 도서, 경제교육, 커리어와 생산성 서비스 같은
  비투자형 브랜드다. 증권사, 금융상품과 투자 추천 성격의 협업은 이번
  범위에서 제외한다.
- 운영은 별도 데이터베이스나 상시 유료 서버 없이 GitHub 기록과 기존
  Slack 알림을 사용한다.

## Required behavior

### 1. 최신 V2 성과 측정 복구

1. V2 Reel이 Instagram에 성공적으로 발행되면 발행 원장의 `externalId`,
   permalink, 발행 시각, 분야와 콘텐츠 유형을 성과 수집 대상으로 자동
   등록한다. 레거시 `data/posts.json`에 별도로 수동 등록해야만 측정되는
   구조를 허용하지 않는다.
2. 각 Reel은 발행 후 24시간, 72시간과 7일 시점에 가능한 범위에서 조회,
   도달, 좋아요, 댓글, 저장, 공유와 총상호작용을 수집한다.
3. 계정 지표는 현재 Instagram API가 허용하는 `follower_count`,
   `profile_views`, `follows_and_unfollows` 등으로 요청한다. 지원되지 않는
   `follows` 요청은 제거한다.
4. Reel 단위 팔로우 수를 API가 제공하지 않으면 계정 팔로워 증분을
   `추정 기여도`로 명시해 저장하며, 단일 Reel의 확정 성과처럼 표현하지
   않는다.
5. API 권한, 지표 미지원, 삭제된 미디어나 토큰 문제로 집계하지 못한 값은
   0으로 기록하지 않는다. `unavailable` 상태, 원인과 재시도 여부를
   GitHub에 남기고 Slack 성과 알림에도 이유를 표시한다.
6. 주간 리포트는 최고 조회수 한 건뿐 아니라 7일 도달 중앙값, 저장률,
   공유율, 참여율, 콘텐츠 유형별 표본 수를 함께 보여 준다. 표본이 적거나
   일부 값이 누락되면 그 한계를 표시한다.

### 2. 핫뉴스 품질 기준선

1. 기존 Economy·Issue 자동 발행은 유지하되, 발행 전 결과물이 다음
   체크를 모두 통과해야 한다.
   - 타이틀만 읽어도 핵심 주체와 사건이 이해된다.
   - 타이틀과 본문의 사실·수치·확정 상태가 원문 근거와 일치한다.
   - 본문은 기사 원문을 어색하게 복사한 문장이나 저작권 표식을 포함하지
     않고 DIEM 문체로 자연스럽게 요약한다.
   - 사진은 기사 핵심 사건과 직접 관련된 장소·기관·제품·사물 또는
     검증된 무인물 개념 사진이며, 무관한 사람을 사용하지 않는다.
   - 이미지 권리, 출처, 의미 일치 근거와 최근 7일 중복 검사를 기록한다.
2. 생성 결과가 위 기준을 통과하지 못하면 품질이 낮은 폴백을 발행하지
   않고 같은 분야의 다음 후보를 전체 파이프라인에 태운다. 안전한 후보가
   없으면 `no_publish`로 끝낸다.
3. 최근 실제 실패 사례와 정상 사례로 제목·본문·이미지 품질 회귀 fixture를
   만든다. 기존에 삭제했던 유형의 결과가 다시 통과하지 않아야 한다.
4. 품질 실패와 `no_publish`는 정상적인 판단 결과로 원장에 보존하고,
   하루 동안 발행이 없을 때는 후보 수와 주요 탈락 이유를 Slack으로
   알린다.

### 3. `DIEM 기초` 4주 승인형 운영

1. `DIEM 기초`는 재테크 초보자가 저장하고 다시 볼 수 있는 경제 개념을
   최근 뉴스 또는 생활 사례와 연결한다. 특정 상품 추천, 수익 약속,
   매수·매도 조언과 기사에 없는 전망을 만들지 않는다.
2. 첫 실험은 주 1편, 총 4편으로 제한한다. 초안은 다음 구조를 갖는다.
   - 표지: 질문 또는 가장 중요한 차이 한 가지
   - 설명: 쉬운 정의, 최근 또는 생활 사례, 흔한 오해나 주의점
   - 근거: 출처 URL, 기준일과 시간이 지나면 재검증해야 하는 항목
3. 정기 준비 실행은 초안, 표지 이미지, Reel 미리보기, 캡션, 출처와
   품질 체크 결과를 GitHub에 `draft` 상태로 기록한다. 이 단계에서는
   Instagram Reel이나 Story를 만들지 않는다.
4. Slack에는 제목, 본문, 표지 미리보기, 출처, 품질 체크 결과,
   `publication_key`와 GitHub Action 링크를 한 메시지로 보낸다.
5. 운영자는 기존 두 운영자용 워크플로 중 `DIEM Economy`의 수동
   `workflow_dispatch`에서 승인할 `publication_key`를 명시한다. Slack의
   인바운드 버튼이나 별도의 웹훅 서버를 추가하지 않는다.
6. 수동 발행은 다음 조건을 모두 확인한 뒤에만 실행한다.
   - 대상이 `draft` 또는 `approved` 상태다.
   - 입력한 `publication_key`가 정확히 일치한다.
   - 준비 당시 콘텐츠 해시와 현재 파일 해시가 같다.
   - 이미 발행된 ID가 아니다.
7. 승인되지 않은 `DIEM 기초`는 예약 시각이 지나도 자동 발행하지 않는다.
   운영자가 반려하면 사유를 기록하고 같은 주에 최대 한 번 다시 준비할 수
   있다. 승인된 콘텐츠만 Reel과 Story를 발행한다.
8. `DIEM 기초`의 발행 결과와 성과는 핫뉴스와 같은 원장에 저장하되
   `content_type: diem_basic`으로 구분한다.

### 4. 4주 품질·성과 평가

1. 실험 종료 조건은 운영자가 승인한 `DIEM 기초` 4편이 발행되고 각
   콘텐츠의 최소 7일 성과 관측이 완료된 시점이다.
2. 종료 리포트는 다음을 핫뉴스와 `DIEM 기초`로 나눠 비교한다.
   - 발행 수와 품질 실패·반려 수
   - 7일 도달 중앙값
   - 저장률과 공유율
   - 평균 시청 시간 또는 API가 제공하는 가장 가까운 유지 지표
   - 프로필 방문과 팔로워 변화
   - 운영자가 삭제하거나 정정한 게시물 수와 사유
3. 한 건의 바이럴 최고값으로 전략을 확정하지 않는다. 중앙값, 표본 수와
   누락 지표를 함께 표시한다.
4. 결과는 GitHub의 Markdown과 JSON으로 남기고 Slack에 요약한다. 운영자는
   결과를 보고 `유지`, `수정 후 재시험`, `중단` 중 하나를 결정한다.

## Acceptance criteria

- [ ] 새로 발행되는 Economy·Issue·`DIEM 기초` Reel이 별도 수동 등록 없이
      24시간, 72시간과 7일 성과 수집 대상이 된다.
- [ ] 계정 지표 요청에서 지원되지 않는 `follows`가 제거되고, API가 제공한
      값과 `unavailable` 원인이 구분되어 저장된다.
- [ ] 성과 수집 실패와 24시간 무발행 사유가 Slack에 사람에게 이해되는
      한국어로 전달된다.
- [ ] 실제 실패 사례 기반 제목·본문·이미지 회귀 테스트가 품질이 낮은
      결과를 차단하고 정상 fixture를 통과시킨다.
- [ ] `DIEM 기초` 준비 실행은 GitHub와 Slack에 완전한 미리보기를 남기지만
      Instagram에는 어떤 외부 변경도 만들지 않는다.
- [ ] 잘못된 ID, 변경된 해시, 미승인 또는 이미 발행된 초안은 수동 발행
      Action에서 실패-폐쇄된다.
- [ ] 정확한 `publication_key`로 승인된 초안만 한 번 발행되고 Reel·Story·
      댓글의 성공 또는 실패 상태가 독립적으로 기록된다.
- [ ] 4주 동안 운영자가 승인한 `DIEM 기초` 4편과 각 7일 성과가 축적된다.
- [ ] 종료 리포트가 최고값뿐 아니라 중앙값, 비율, 표본 수, 누락과 정정·
      삭제 기록을 포함한다.
- [ ] 실험 기간에는 브랜드 아웃바운드, 광고 안내 고정 게시물과 자동
      `DIEM 기초` 발행이 실행되지 않는다.

## Constraints

- 별도 데이터베이스와 상시 유료 인프라를 추가하지 않는다.
- GitHub 파일, 기존 GitHub Actions와 기존 Slack 발신 경로를 사용한다.
- 운영자용 발행 워크플로는 `DIEM Economy`, `DIEM Issue` 두 개를 유지하며
  `DIEM 기초`를 위한 세 번째 워크플로를 만들지 않는다.
- Slack은 미리보기와 알림의 발신 채널로만 사용한다. 인바운드 승인 서버나
  인터랙티브 버튼은 이번 범위에 포함하지 않는다.
- Instagram 액세스 토큰과 API 비밀 값은 저장소 파일이나 Slack 메시지에
  기록하지 않는다.
- 기존 Economy·Issue 발행 기록과 과거 게시물은 삭제하거나 다시 쓰지
  않는다.
- DIEM 미션의 개인별 투자 추천 금지, 근거 없는 전망 금지와 기사 정확성
  원칙을 유지한다.

## Verification

- Automated:
  - V2 발행 원장에서 성과 수집 대상이 자동 파생되는 단위 테스트
  - 24시간·72시간·7일 due-window와 중복 수집 방지 테스트
  - 유효·미지원·권한 실패 Instagram 지표 응답 fixture 테스트
  - 주간 중앙값·비율·누락 표기 리포트 테스트
  - 실제 실패 사례 기반 제목·본문·이미지 품질 회귀 테스트
  - `DIEM 기초` 준비가 외부 발행 함수를 호출하지 않는 테스트
  - publication key·해시·상태·중복 발행에 대한 실패-폐쇄 테스트
  - Reel·Story·댓글 독립 상태 전이 테스트
  - `npm run test`
  - `git diff --check`
- Manual:
  - GitHub Actions 수동 준비 1회 후 Slack 메시지와 GitHub 초안 대조
  - 잘못된 ID와 변경된 초안으로 발행이 거절되는지 확인
  - 승인된 테스트 초안 1건의 Reel·Story·댓글 결과와 원장 대조
  - Instagram Insights와 GitHub 24시간 스냅샷 표본 1건 대조
  - 4주 종료 리포트의 표본 수·중앙값과 원본 기록 대조

## Out of scope

- 4주 실험 중 브랜드에 직접 제안하거나 협업 문의를 발송하는 일
- 공개 미디어킷, 가격표, 광고 안내 고정 게시물과 브랜드 포트폴리오 공개
- 유료광고, 제품 협찬, Gifts, 구독과 제휴 링크 운영
- 증권사, 투자상품과 매수·매도 성격의 브랜드 협업 준비
- `DIEM 기초`의 무승인 자동 발행
- Slack 인터랙티브 승인 버튼과 이를 받기 위한 상시 서버
- 별도 데이터베이스, 유료 분석 서비스와 신규 유료 이미지 서비스
- 기존 V2 뉴스 파이프라인 전체 재작성

## Risks and rollback

- Instagram API가 일부 지표를 제공하지 않으면 해당 지표만
  `unavailable`로 유지하고 나머지 측정을 계속한다. 추정치를 확정값으로
  승격하지 않는다.
- 주간 초안 품질이 낮으면 해당 초안을 반려하고 한 번 재생성한다. 그래도
  통과하지 못하면 그 주를 미발행으로 기록하며 낮은 품질로 채우지 않는다.
- 승인 경로에 결함이 있으면 `DIEM 기초`의 수동 발행 입력을 비활성화하고
  준비 및 Slack 미리보기까지만 유지한다. Economy·Issue 예약 발행은 영향을
  받지 않아야 한다.
- 성과 수집 변경이 기존 원장을 손상시키면 읽기 전용 어댑터를 제거하고
  마지막 정상 Git 기록으로 되돌린다. 과거 발행 원장 자체는 수정하지 않는다.
- 4편과 7일 관측 후 저장·팔로우 전환 개선이 없거나 운영 부담이 크면
  `DIEM 기초`만 `inactive`로 전환하고 핫뉴스 파이프라인을 유지한다.
