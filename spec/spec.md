# Feature: DIEM 성과 학습 루프와 편집 복구력 강화

## 2026-08-23 approved amendment: 주간 품질 안정화

### Outcome

최근 발행량 증가와 카테고리 이탈, 과장된 확정 표현, 숫자 문맥 혼합,
무관한 웹 이미지 선택을 자동 발행 전에 차단한다. 핫뉴스 폴링은 유지하되
기본 발행은 KST 하루 Economy 1편과 Issue 1편으로 제한한다.

### Required behavior

1. 같은 KST 날짜에 이미 발행된 카테고리는 후속 예약 실행을
   `daily_publication_budget_exhausted`로 종료하고 Slack에 사유를 남긴다.
2. Economy의 주 사건은 돈·주거·금융·고용·산업·시장 변화여야 하고,
   Issue는 다수에게 의미 있는 정책·공공안전·외교·사법·정치 사건이어야 한다.
   사적 상담, 연예인 후폭풍, 신체 시술 호기심, 주차·온라인 화제는 공공 제도
   변화가 없으면 발행하지 않는다.
3. 보도·증언·검토 상태의 제목과 본문은 `확정·결정·시행`으로 강화하지 않는다.
   하나의 문장에 여러 숫자를 결합할 때는 같은 원문 근거 문장에 그 숫자들이
   함께 있어야 한다.
4. 이미지 검색은 우선순위가 다른 검색 의도의 후보를 한 풀에 섞지 않는다.
   최종 후보는 실제 이미지 기반 검수에서 기사 사건·국가·상징·사람 안전을
   통과해야 하며, 검수 실패나 모델 장애 시 DIEM 원본 이미지로 닫는다.
5. Control/Growth 실험은 이 변경 배포 후 7일간 삭제·정정·이미지 사고가
   0건일 때만 별도 스펙으로 활성화한다.

### Acceptance criteria

- [ ] 일반 자동 발행은 하루 Economy 1편 + Issue 1편을 넘지 않는다.
- [ ] 이번 주 오분류 사례 fixture가 기대 카테고리 또는 명시적 리젝트가 된다.
- [ ] `CXMT / 삼성 탈취 확정`과 같은 증언→확정 제목이 거부된다.
- [ ] 서로 다른 정책대출 기준 숫자를 한 문장에 섞으면 거부된다.
- [ ] 정책대출→주식차트, 공깃밥→코스피, 이란→청와대, 한국정치→미국
  투표함 후보가 웹 이미지 단계에서 선택되지 않는다.
- [ ] 이미지 검수 불능은 무검수 웹 이미지 발행이 아니라 원본 이미지로 끝난다.
- [ ] 기존 Story·댓글·대댓글·7일 이미지 중복·성과 수집이 유지된다.
- [ ] `npm run test`와 `git diff --check`가 통과한다.

### Constraints and rollback

- 별도 DB·상시 서버·신규 유료 서비스는 추가하지 않는다.
- 기존 Groq 계정에서 vision 모델을 사용할 수 있을 때만 실제 이미지 검수를
  수행하며, 사용할 수 없으면 웹 이미지 경로를 fail-closed한다.
- 발행 예산은 환경 변수로 되돌릴 수 있게 격리하되 기본값은 카테고리당 1이다.
- 성장 실험과 새로운 Reel 포맷은 이번 구현 범위에서 자동 활성화하지 않는다.

## 2026-08-14 approved amendment

### Medical safety claim scope

1. 의약품 안전 기사는 `당국이 발표한 경고·권고·행동 지침`과
   `의학적 인과관계·안전성 근거의 충분성`을 서로 다른 상태로
   기록한다.
2. 확정된 복용 주의나 중단 권고를 `미확정`으로 표현하지 않는다.
3. 근거가 제한적이라는 설명은 해당 근거의 한계에만 붙이고,
   기사 전체나 공식 권고 자체를 부인하는 제목으로 확장하지 않는다.

### DIEM Basic save-and-follow trial

1. `DIEM Basic`은 실시간 기사에서 주제를 뽑거나 GitHub Action에서
   LLM으로 새로 생성하지 않는다. 편집자가 커리큘럼 주제를 먼저
   정하고, 공식·1차 출처 두 곳 이상으로 크로스체크한 저장형
   콘텐츠만 발행한다.
2. 첫 4편은 `ISA 세제 혜택`, `ETF·ETN 차이`, `고정·변동금리`,
   `신용점수와 대출금리`를 순서대로 사전 제작해 Git에 저장한다.
3. 각 패키지는 고정 ID·순서·상태, 2줄 표지 제목, 3문장 본문,
   이모지 댓글·해시태그 대댓글, 사람 얼굴을 쓰지 않는 DIEM 원본
   시각 모티프, 사용 음원, 출처·검증일·재검토 기한을 함께 담는다.
4. 예약 Action은 다음 `ready` 패키지와 Git에 저장된 최종 표지·Reel의
   해시를 검증하고 Instagram에 업로드만 한다. 주제 선정, 뉴스 검색,
   LLM 원고 생성, 웹 이미지 검색, 렌더링과 자동 내용 변경은 금지한다.
5. 주 1회 일요일 09:30 KST에 한 편씩 발행하고, 수동
   `publish_basic`은 콘텐츠 ID를 지정하거나 다음 `ready` 패키지를
   선택할 수 있다. 이미 발행한 ID는 두 번 발행하지 않는다.
6. 검증일이 지나거나 출처·원고 해시가 달라지면 자동 발행을
   닫고 `needs_refresh`로 기록한다. 발행할 `ready` 패키지가 없거나
   렌더링·발행이 실패하면 사유와 Action 링크를 Slack으로 알린다.
7. 표지 상단 유형은 Economy가 아닌 `DIEM Basic`으로 고정하고,
   4편 모두 같은 타이포그래피·색상·문장 구조를 쓰되 주제별
   사물·구조 모티프로 시각적 구분을 둔다.

### DIEM Basic acceptance criteria

- [ ] Git에 저장된 4개 패키지가 스키마, 2줄·14자 제목, 3문장·120자,
  1·3문장 끝 이모지, 정확히 15개 해시태그 계약을 통과한다.
- [ ] 각 편에 서로 다른 기관의 공식·1차 출처가 두 곳 이상 있고,
  각 핵심 주장이 최소 한 출처에 직접 연결된다.
- [ ] GitHub Action 정적 테스트가 예약·수동 DIEM Basic 경로에
  Groq/LLM·뉴스 선정·웹 이미지 검색이 없음을 보장한다.
- [ ] 정해진 순서, 중복 방지, 내용 해시 불일치, 재검토 기한 초과,
  큐 고갈과 Slack 실패 알림 경로가 테스트로 고정된다.
- [ ] 제작 스킬과 템플릿에 주제 선정, 자료 수집·크로스체크,
  문안·디자인, 승인, 저장, 발행 후 학습 절차가 남는다.

## 2026-08-15 approved amendment

### DIEM Basic five-card lesson Reel

1. DIEM Basic은 표지 한 장을 7초 동안 보여 주는 형식이 아니라, 캡션을
   열지 않아도 핵심 학습을 마칠 수 있는 5장 교육 Reel로 제작한다.
2. 장면 순서는 `질문 표지 → 쉬운 정의 → 작동·비교 → 오해·주의 → 한 줄
   정리`로 고정한다. 기본 노출 시간은 3초·4초·5초·4초·3초이며, 단순
   페이드만 사용해 최종 길이를 19초로 맞춘다. 줌·흔들림·인물 영상은 쓰지
   않는다.
3. 각 정보 장면의 사실 문구는 `claims`의 ID에 직접 연결한다. 출처에 없는
   숫자·인과·권유를 장식 문구로 새로 만들지 않는다.
4. 교육 시리즈는 뉴스 Reel과 구별되는 웜 아이보리 종이 배경, 짙은 네이비
   본문, 코발트 핵심색, 민트 보조색을 사용한다. 날짜와 Economy/Issue 표시는
   제거하고 `DIEM BASIC`, `경제기초 NN`, `현재 장 / 전체 장`을 모든 장에
   표시한다.
5. 배경 사진과 사람 얼굴은 금지한다. 비교표, 흐름도, 산식, 체크리스트처럼
   내용을 직접 설명하는 프로젝트 원본 벡터 요소만 사용한다.
6. Git 패키지에는 5장의 1080×1920 PNG, 첫 장과 동일한 `cover.png`, 검증된
   음원이 전체 구간에 들어간 H.264/AAC `reel.mp4`, 모든 파일의 SHA-256을
   저장한다. GitHub Action은 계속 완성된 Reel을 검증하고 발행만 한다.
7. 기존 3문장 본문·댓글·해시태그는 영상의 보충 설명으로 유지하되, 핵심
   설명을 캡션에만 남겨 두지 않는다.
8. 수업 카드 본문과 보충 캡션은 딱딱한 `합니다체`와 번역문식 추상 어순 대신
   자연스러운 `해요체`로 쓴다. 독자가 실제로 품을 질문에서 시작하고, “먼저
   봅니다”, “오해부터 바로잡습니다”처럼 콘텐츠 진행을 설명하는 문구는 쓰지
   않는다. 단, 이름·숫자·조건·예외·불확실성은 검증된 `claims`와 같아야 한다.

### Five-card acceptance criteria

- [ ] 4개 패키지 모두 정확히 5장이고 장면 역할, 순서, 노출 시간과 총 19초
  계약을 통과한다.
- [ ] 모든 정보 장면이 하나 이상의 검증된 주장 ID에 연결되고, 요약 장면도
  앞서 검증된 주장만 재사용한다.
- [ ] 모든 카드가 1080×1920이며 `DIEM BASIC`, `경제기초 NN`, 장 번호를
  표시하고 날짜·Economy·Issue·사람·웹 사진을 포함하지 않는다.
- [ ] 최종 Reel은 1080×1920 H.264, 30fps, AAC stereo, 48kHz, 19초이며
  5장 사이에는 정적 페이드만 존재한다.
- [ ] 5장·표지·Reel의 저장된 해시가 실제 파일과 모두 일치하지 않으면
  자동 발행을 실패-폐쇄한다.
- [ ] 4개 패키지의 카드 본문과 캡션이 한국어 편집 검사를 통과하고, 금지된
  AI식 진행 안내 문구나 일률적인 `합니다체`가 남아 있지 않다.

## Outcome

DIEM의 과거·신규 Reel 성과를 같은 관찰 구간끼리 비교해 잘된 패턴과
부진한 패턴을 GitHub 리포트로 누적하고, 충분한 표본에서만 다음 기사 선정에
작은 가중치로 반영한다. 동시에 좋은 기사가 표지 제목 생성 실패만으로
버려지지 않게 제한된 LLM 제목 재정제 단계를 두고, 맥락 사진 검색 범위를
권리 확인 가능한 무료 소스로 확장한다.

## Required behavior

### 1. 반복 가능한 성과 분석

1. 발행 원장의 `24h`, `72h`, `7d` Instagram 지표를 서로 섞지 않고 분석한다.
   목표 관찰 시각보다 허용 오차를 넘겨 수집된 늦은 백필은 원장에
   보존하되 성과 비교와 선정 prior 표본에서 제외한다.
2. 카테고리별 조회·도달 중앙값, 공유율, 저장률, 참여율, 평균 시청 시간과
   계정 팔로워 증분 추정치를 기록한다. 누락 지표는 0으로 취급하지 않는다.
3. 표본이 5편 미만이면 승자·부진 패턴을 확정하지 않는다. 충분한 표본에서
   상위·하위 성과와 제목·주제·이미지·음악 특성의 lift를 계산한다.
4. 결과를 `data/reports/diem-performance.json`과 Markdown에 원자적으로 저장한다.
5. 이후 기사 선정에는 충분한 표본으로 검증된 주제 특성만 제한된 범위로
   가감한다. 품질·정확성·중복·시의성 게이트를 우회하지 않는다.
6. 프로젝트 전용 Codex skill과 운영 플레이북을 저장해 같은 분석을 반복할
   수 있게 한다.

### 2. 제목만 실패한 편집 결과 복구

1. 원문 제목 길이는 발행 실패 사유가 아니다. LLM의 캡션·사실 정렬은
   유효하지만 제목 후보만 실패한 경우, 같은 모델에 제목 JSON만 한 번
   재요청한다.
2. 재요청은 고정된 기사 프레임과 사실, 기존 캡션을 바꾸지 않으며 정확히
   2줄·합계 14자·주체와 사건·확정 상태를 지키게 한다.
3. 제목 재정제가 실패하면 다음 모델을 시도하고, 모든 모델이 실패하면 기존
   결정대로 같은 분야의 다음 기사 후보를 전체 파이프라인에 태운다.
4. 결정론적 저품질 제목·본문 폴백은 자동 발행에 사용하지 않는다.
5. 모델별 원본 실패, 제목 재정제 시도와 최종 실패 사유를 원장에 보존하고
   Slack `no_publish` 알림에서 가장 유용한 이유를 보여 준다.

### 3. 이미지 맥락과 공급원 확대

1. 기존 Pexels·Unsplash·Wikimedia에 Openverse의 상업 이용·수정 허용
   이미지를 추가한다. CC0, Public Domain, CC BY, CC BY-SA만 허용한다.
2. 부동산 거래, 현금·지역 지원, 노동 현장 등 반복 실패 주제에 구체적인
   사물·장소 중심 영문 검색어를 우선한다.
3. 기존 무관 인물 차단, 실제 인물 최후 단계 사용, 맥락 적합성, 권리,
   해상도와 최근 7일 이미지 중복 금지 조건은 유지한다.
4. 모든 공급원·검색어·탈락 사유와 최종 폴백 사유를 원장에 기록한다.

### 4. 음악 판단

1. 현 음원 수를 즉시 늘리지 않는다. 성과 리포트에 트랙·무드 사용 분포와
   특정 트랙 편중 경고를 추가한다.
2. 한 트랙이 비민감 Reel의 20%를 넘거나, 충분한 표본에서 반복 피로가
   관측될 때만 새 음원 추가를 제안한다.

## Acceptance criteria

- [ ] 성과가 없는 저장소에서도 리포트가 `insufficient_data`로 안전하게 생성된다.
- [ ] 관찰 구간과 카테고리별 중앙값·비율·누락·표본 수가 기록된다.
- [ ] 충분한 표본이 없으면 성과 가중치가 0이며, 있더라도 상한을 넘지 않는다.
- [ ] 긴 원문 제목 사례에서 유효 캡션을 유지한 채 제목 전용 재정제가 성공한다.
- [ ] 제목 재정제까지 실패하면 상세 모델 시도가 원장에 남고 다음 후보로 이동한다.
- [ ] Openverse 허용 라이선스만 후보로 들어오며 무관 인물·최근 중복 게이트를 통과해야 한다.
- [ ] 수동 `collect_insights` 작업으로 발행 없이 성과 수집과 리포트 갱신이 가능하다.
- [ ] 전용 skill과 Markdown 플레이북이 저장되고 skill 검증을 통과한다.
- [ ] `npm run test`와 `git diff --check`가 통과한다.

## Constraints

- 별도 DB, 상시 유료 서버, 신규 유료 이미지·분석 서비스를 추가하지 않는다.
- GitHub 원장과 Actions, 기존 Instagram Graph API와 Slack을 사용한다.
- 한 건의 바이럴이나 부진 Reel로 주제를 금지하거나 자동 전략을 확정하지 않는다.
- 기사 사실성, 제목 확정 상태, 저작권, 무관 인물 차단과 7일 중복 금지를
  성과 가중치보다 항상 우선한다.
- 음악 파일은 이번 범위에서 추가하지 않는다.

## Verification

- 제목 전용 재정제 성공·실패·다음 후보 전환 단위 테스트
- 상세 편집 실패 진단 원장 보존 테스트
- 성과 리포트의 관찰 구간 분리, 중앙값, 표본 하한과 가중치 상한 테스트
- Openverse 라이선스 정규화·차단·선정 테스트
- GitHub Actions 수동 성과 수집 경로 정적 테스트
- skill quick validation
- `node .codex-harness/scripts/verify-project.mjs`

## Out of scope

- Instagram 게시물 삭제·재발행
- 유료 광고, 브랜드 영업, Gifts 또는 구독 기능
- 기사 원문·언론사 사진의 권리 확인 없는 재사용
- 표본 미달 상태의 자동 주제 블랙리스트
- 신규 음원 다운로드·라이선스 검수

## Risks and rollback

- 성과 API 지표가 비어 있으면 리포트만 `insufficient_data`로 유지하고 선정
  점수에는 반영하지 않는다.
- 제목 재정제가 rate limit을 악화시키면 한 번의 제한된 호출을 비활성화해
  기존 다음 후보 전환으로 돌아간다.
- Openverse 메타데이터가 불충분하면 후보가 기존 적합성 게이트에서 탈락하고
  기존 공급원 또는 중복되지 않는 프로젝트 원본 타이포그래피로 돌아간다.
- 성과 가중치가 품질을 낮추면 리포트 생성은 유지하고 선정 prior만 0으로
  비활성화한다.
