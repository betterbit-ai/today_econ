주간 뉴스 4~6편과 Basic1편, 총5~7편이면 14일에 분야별10편을 모으기 어렵다.
달력보다 표본을 우선하고, 약한 기사로 숫자를 채우지 않는다.
첫 화면 실험의 각 안 10편도 실제 발행량에 따라 4~6주 이상 걸릴 수 있다.

- [ ] 품질 사고 1건이면 관련 실험을 중단하고 flash 안전 상태로 복구한다.
- [ ] 계정/API 접근 오류가 반복되면 발행 재시도와 성과 수집을 분리한다.
- [ ] 4주 도달·효용 개선이 없으면 먼저 질문·소재·첫 답을 수정한다.
- [ ] 8주에도 개선이 없으면 발행량 확대 대신 적은 주간 편집·저장형 설명을 재설계한다.
- [ ] 12주 평가에서 도달·효용·순증·제작시간을 모두 보고 유지·수정·축소를 결정한다.

## 8. explain은 증거를 채운 뒤 재개

- [ ] 분류 shadow 40건, 서로 다른 sample ID, 오분류·사고 0.
- [ ] explain 초안10건, 서로 다른 ID, 역할 의미·claim·원문 span 오류0.
- [ ] production Vision 검수5회 연속 성공, 실행ID, 모델·전송오류0.
- [ ] 실제 evidence 파일을 만들고 npm run diem:explain-gates 통과 확인.
- [ ] 별도 배포에서 재개 여부를 정하고 분야별3일 간격·누적5편 canary 상한 준수.
- [ ] 장면마다 답 하나와 읽기 시간을 실제 모바일에서 검수.
- [ ] 사고1건이면 다시 차단하고 기록을 보존.

숫자만 evidence에 채우거나 환경변수 하나로 gate를 우회하지 않는다.
