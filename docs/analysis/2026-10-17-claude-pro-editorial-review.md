# DIEM Claude Pro / Sonnet 5.5 원고 생성 전환 검토

검토일: 2026-10-17. 사용자가 Claude **Pro** 구독을 확인했다. 이 문서는 도입 검토안이며 Claude 연동이 구현·인증·성능 검증됐다는 뜻이 아니다. 기존 자동 발행은 유지한다.

## 이후 구축 상태

사용자가 검증 구축을 승인해 공식 Claude Code CLI를 Actions에서 직접 호출하는 shadow 비교 경로를 구현했다. 같은 generateEditorial의 재교정을 재사용하기 위한 구현 선택이며 구독 OAuth·공식 클라이언트 경계는 유지한다. 고정10기사·보호10사례·독립 HTML/JSON/Markdown 결과를 제공한다. 실제 인증·모델 비교 상태와 사용 방법은 [비교 실행 안내](../diem-editorial-comparison-ko.md)를 따른다. 아래의 전환·자동발행 연계는 여전히 제안이며 운영 provider는 바꾸지 않았다.

## 결론

Sonnet 5.5는 원고 생성·교정의 비교 대상으로 적합하다. 공식 Claude Code GitHub Action을 구독 OAuth로 실행하고 결과 JSON을 기존 검증·렌더·발행 코드에 넘기는 방식이 현재 규모에 맞는다. 구독 토큰을 Groq/일반 REST 클라이언트에 넣지 않는다. 원고 모델 교체만으로 이미지 매핑·Instagram 인증·기존 검증기의 과잉 차단은 해결되지 않는다. 전면 전환보다 게시 없는 비교를 먼저 한다.

## 공식 지원과 비용 경계

- [공식 GitHub Actions 문서](https://code.claude.com/docs/en/github-actions): Pro·Max·Team·Enterprise의 구독 OAuth Secret을 지원하며 예약 이벤트에서 자동 실행할 수 있다. OAuth 실행은 API 종량제가 아닌 구독 사용량을 소비한다.
- [공식 인증 문서](https://code.claude.com/docs/en/authentication): 로컬 `claude setup-token`으로 CI용 토큰을 발급한다. Secret 이름은 `CLAUDE_CODE_OAUTH_TOKEN`이다. 원문을 채팅·파일·로그·공개 저장소에 넣지 않는다.
- [Sonnet 공식 안내](https://www.anthropic.com/claude/sonnet): 모델 ID `claude-sonnet-5-5`. 실제 Pro 인증 환경에서 모델 접근을 다시 확인해야 한다.
- [Action 구조화 출력](https://github.com/anthropics/claude-code-action/blob/main/docs/usage.md#structured-outputs): JSON Schema 결과를 다음 Action 단계로 넘길 수 있다. JSON 형식 검증은 사실 정확성 검증을 대신하지 않는다.
- [사용량 안내](https://code.claude.com/docs/en/costs): 개인 Claude 사용과 한도를 공유하므로 Pro로 일정한 일일 처리량을 보장할 수 없다. 추가 사용량 결제·API 자동 전환은 켜지 않는다. 구독료가 이미 지출돼도 전체 운영비가 무료라고 표현하지 않는다.
- [인증 사용 경계](https://code.claude.com/docs/en/legal-and-compliance): 공식 Claude Code/Action 경로에서 본인 계정을 사용하며 구독 OAuth를 제3자 서비스의 일반 모델 API로 중계하지 않는다.

검토 당시 GitHub Secret 목록에 Claude 토큰은 없고 현재 shell PATH에 Claude CLI도 없다. 토큰 원문이나 개인 로그인 파일은 조회하지 않았다. 실제 모델 비교 결과는 **없음**이다.

## 권장 연결 구조

기존 수집 → 인기·신선도·분류·중복 선정 → 잠긴 frame·원문 근거 입력 → Claude Code Action 원고 JSON → 기존 의미·상태·제목 검사 → 기존 이미지 선택·검수 → 6초 렌더 → 기존 Instagram 발행·원장.

1. `src/v2/publisher.js`는 이미 `callModel` 의존성 주입을 지원하지만, 공식 Action은 Node 함수 안에서 호출할 수 있는 Groq endpoint가 아니다. Action 단계와 원고 JSON 수신 경계가 필요하다.
2. 1차 비교는 기존 economy workflow에 수동 shadow operation을 추가하는 방안이 가장 작다. 새 상시 workflow·DB·외부 API를 추가하지 않는다. shadow는 Instagram/Slack 쓰기 Secret을 받지 않고 원장·상한을 변경하지 않는다.
3. 원문·frame·출처 해시는 기존 candidate-pack/선정 데이터에서 만든다. 모델에 저장소 전체·발행 토큰·쉘 실행·코드 수정 권한을 주지 않는다. 기사 안의 지시는 자료로만 취급한다.
4. 모델 출력은 버전·모델·원문 해시·시도 단계와 연결한다. `structured_output`은 환경 변수 또는 파일로 전달해 JSON으로 파싱하고 shell 명령에 직접 삽입하지 않는다.
5. 기존 `generateEditorial`의 파싱·검증·조립 경계를 재사용한다. 기존 daily-package 검증은 근거 해시/claim/시각 자산 계약을 참고할 수 있으나 현재 ChatGPT용 예약 canary와 수동 발행 모드를 무조건 재활용하지 않는다. 해당 흐름의 예약·신선도·중복·일일 상한을 각각 검증해야 한다.
6. 검증기 통과 결과를 별도 경로로 직접 발행하지 않는다. 기존 publishPreparedPublication과 durable idempotency를 유지한다.

## Pro에 맞춘 게시 없는 비교

- 먼저 최근 실제 기사 10개를 고정한다: 경제5·시사5, 숫자/기간/분모/인용/부인/잠정 상태·본문 찌꺼기·부동산 홍보성 사례 포함. 원문·수집 시각·해시를 고정한다.
- 합성 공격/보호 사례는 별도10건으로 둔다. 정상 표현과 잘못된 표현을 쌍으로 만들어 모델과 별개로 검증기의 과잉 차단도 확인한다.
- 실제 기사 비교는 5개씩 두 묶음으로 진행한다. 기존 GPT-OSS 초안이 완전하게 보존되지 않은 사례는 baseline을 재생성하고 기존 성공 원장 결과와 구분한다. 이전 성공 사례만으로 선정하지 않는다.
- 두 모델에 동일한 원문·사건 frame·계약을 제공한다. 초기 생성, 본문 복구 최대1회, 제목 복구 최대1회를 각각 기록하고 공정 비교에서 모델별 fallback은 제외한다. 현재 120B→20B 운영 체인의 최종 결과는 별도 참고값이다.
- 측정: 첫 응답 통과율, 복구 후 통과율, 실제 의미 오류, 과잉 차단, 한국어 문장·제목 품질, 소요 시간, 모델 호출 수, 구독 제한 오류. 숫자를 모두 지워 통과한 결과는 정보 손실도 별도 평가한다.
- 인간 검토는 이 제한된 도입 평가에만 사용한다. 매일 승인하는 운영으로 바꾸지 않는다. 10건은 도입 판단용 작은 표본이며 도달·시청 성과 우위를 증명하지 않는다.

### 제안하는 전환 기준

10건 중 복구 후8건 이상이 기존 gate를 통과하고, 사람 검토에서 사실·상태·이미지 주제 사고0건이어야 한다. 동일 baseline보다 승인 가능한 원고가 최소2건 늘거나, 비슷한 통과율에서 교정 부담이 뚜렷이 줄어야 한다. 원문에 있는 표현을 검사기가 잘못 막은 경우를 모델 실패와 분리한다. 이 숫자는 검토용 제안이며 성능 결과나 현재 스펙의 확정값이 아니다.

## 통과 후 제한 도입안

원고 provider 설정으로 되돌릴 수 있게 하고 기존 예약·일일 분야별1편·6초·음악을 유지한다. 처음에는 선정 후 호출에만 Sonnet을 쓰고 새 평가에서도 후보·호출 상한을 고정한다. 구독 한도 초과·인증 실패 시 무한 재시도·별도 유료 API 자동 전환은 하지 않는다. 검증된 기존 경로로 제한 복귀하거나 다음 예약으로 넘기며 이유를 기록한다. 기존 Groq Vision은 별도 유지한다. 첫3편의 실제 결과를 확인하고 24h·72h·7d를 섞지 않고 측정한다.
