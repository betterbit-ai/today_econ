## 1. 지금 가장 중요한 판단

**성과 하락은 실제다. 다만 지금 필요한 것은 발행량 확대가 아니라, 정확하게 독자에게 도움이 되는 콘텐츠를 영상 안에서 전달하고 그 결과를 제대로 측정하는 일이다.**

일반 뉴스의 정시 24시간 도달 중앙값은 7월 25일~8월 22일 대비 최근 성숙한
10월 7일~12일 표본에서 Economy 620.5→137명, Issue 1,207→137.5명으로 줄었다.
각각 약 77.9%, 88.6% 감소다. 최근 표본은 분야별 6편이므로 하락의 크기는
참고하되, 새 전략의 장기 효과를 확정할 표본으로 보지는 않는다.

현재 계정 상태 화면은 **도달 범위 제한 없음·비팔로워 추천 가능·모든 기능 사용 가능**을
표시했다. 따라서 지금의 낮은 조회수를 섀도밴으로 설명할 근거는 없다.
추천 자격과 실제 추천량은 다르며, 과거 모든 날짜의 상태까지 확인한 것은 아니다.

반면 GitHub 원장에는 10월 13일 Instagram API 발행의
**“400: User access is restricted”** 오류가 있다. 실제 게시물 ID가 없으므로
그 작업은 조회수 0인 게시물이 아니라 발행 실패다. 현재 UI 정상 상태와 이 API 오류를
함께 기록하고, 원본 error code·subcode·권한·계정 연결 상태를 따로 확인해야 한다.

가장 먼저 처리할 문제는 다음 다섯 가지다.

1. 10월 6일 개선 코드가 실제 운영 main에 들어가지 않았다.
2. 최근 발행 12편 모두 생성 배경이며, 그중 5편에서 모델 미존재 오류 7회가 확인됐다.
3. 경제 콘텐츠에 전쟁·개인 사건·정치적 비판이 섞이고, 숫자 제목에는 기간·분모 오류가 있다.
4. 6초 뉴스 영상은 제목만 보여준다. 핵심 설명을 읽으려면 캡션을 따로 열어야 한다.
5. 기초 콘텐츠와 프로필 전환 구조가 준비 단계에 머물거나 후속 공급이 끊겼다.

이미지 반복과 정적 영상이 각각 하락을 얼마나 일으켰는지는 현재 데이터로 분리할 수 없다.
그러나 모델 오류, 미배포 코드, 오분류, 제목 의미 오류, 영상의 정보 부족은 직접 확인한 문제다.

### 3.3 시청 지표를 읽을 때의 주의

## 4. 현재 시청자에게 보이는 제품의 문제

### 4.1 제목만 읽고 넘어가도 콘텐츠가 끝난다

일반 flash는 날짜·카테고리·제목·계정명을 담은 표지 한 장을 6초 동안 보여준다.
기사 설명 3문장은 캡션에 있다. 영상만 보는 사람에게는 설명이 전달되지 않는다.

독자가 “코인세 시행 / 반발 확대”를 읽었을 때 알 수 있는 것은 사건 이름뿐이다.
누가 영향을 받는지, 무엇이 달라지는지, 확정된 것과 아직 논의 중인 것이 무엇인지
알려면 캡션을 열어 긴 문장을 읽어야 한다.
경제를 쉽고 짧게 이해시키겠다는 약속이 첫 화면에서 이행되지 않는다.

최근 실제 피드에서도 아래 문구가 보였다.

- “트럼프 / 관세 발언”: 발언 내용이 없어서 독립적으로 이해하기 어렵다.
- “코인세 시행 / 반발 확대”: 시행 상태와 독자에게 필요한 조건이 화면에서 빠진다.
- “국힘 구자근 / 최태원 광주 / 오르막·내리막 비판”: 사전 맥락 없이는 사건을 이해하기 어렵다.
- “실온 밥 재가열 / 20대간·신장손상”: 단어가 붙어 읽기 어렵고 사건의 적용 범위가 흐리다.

위 문구는 발행 기록을 인용한 것이며, 해당 기사 사실을 이 보고서가 재검증해 승인한 것은 아니다.

**가장 작은 실험:** 검증된 핵심 사실 한 줄을 제목 아래 넣는다.
첫 화면에서 주체·변화·조건이 이해되도록 하고, 새로운 전망은 만들지 않는다.
다음 카드나 캡션을 열기 전에도 하나의 답을 얻을 수 있어야 한다.
문장을 늘려 화면을 빽빽하게 만들지 말고 모바일 실제 크기로 읽기 테스트를 한다.

### 4.2 explain에는 설명이 있지만 장면의 의미가 보장되지 않는다

현재 원격 코드는 사건 종류를 보고 explain을 선택하고 3문장에
“무슨 일 / 내게 미치는 영향 / 앞으로 확인할 사실” 역할을 순서대로 붙인다.
문장 2가 진짜 독자 영향인지, 문장 3이 실제 다음 확인 사항인지 별도 증거가 부족하다.
역할 제목을 붙였다는 사실이 내용의 적합성을 보증하지 않는다.

10월 7일 관세 explain에서 투자 언급이 독자 영향 장면에 들어가고,
정치적 홍보 해석이 다음 확인 장면에 들어간 것이 그 예다.
60~115자 문장을 몇 초 안에 읽어야 하는 장면도 있어, 실제 모바일 독해 검증이 필요하다.

로컬 10월 6일 변경은 이 문제를 줄이려고 40건 분류·10건 explain 초안·Vision 5회 성공의
증거 gate를 두었다. 아직 배포되지 않았고 실제 증거 파일도 충족하지 못했다.
새 포맷을 늘리기 전에 이 운영 간극부터 닫아야 한다.

### 4.3 기초 콘텐츠는 가장 중요한 차이를 늦게 알려준다

ETF·ETN 1·2번 실제 카드를 확인했다.
첫 장은 일반적인 질문, 두 번째 장은 두 상품 모두 거래소에서 주식처럼 거래된다는 공통점이다.
독자가 궁금한 핵심 차이와 발행사 신용위험은 뒤쪽에 있다.
평균 시청 약 1초인 상황에서 가장 가치 있는 설명을 뒤에 두면 대다수에게 닿지 않을 수 있다.

형식을 재시험할 때는 “질문 → 공통점 → 차이”보다
“직접 답 한 가지 → 쉬운 구조 → 주의할 조건” 순서부터 검토한다.
예를 들어 기존 검증된 주장으로 첫 화면에
“ETF는 펀드, ETN은 증권사가 발행한 증권이에요”를 제시하고,
발행사 신용위험과 양쪽 모두 원금 비보장이라는 조건을 빠뜨리지 않는다.
최종 원고는 최신 KRX·금융당국 원문을 다시 검증해야 한다.
[KRX 증권상품 소개](https://open.krx.co.kr/contents/OPN/01/01030100/OPN01030100.jsp)

지금의 5장·19초 계약을 바로 변경할 필요는 없다.

### 5.1 개선이 실제로 배포됐는지 확인해야 한다

원격 운영은 feature schema v2이고 qwen/qwen3.6-27b를 사용한다.
로컬 v3는 분류 복합 조건·reach 분리·explain gate·새 Vision 모델을 포함한다.
“작성됨”, “테스트됨”, “main 반영”, “Action 실행”, “실제 발행 확인”을 각각 다른 상태로 관리한다.
이번 진단에서 열린 PR은 없었다.
원장 기록이 많은 main을 덮어쓰거나 강제 푸시하지 말고 작은 변경으로 통합해야 한다.

### 5.2 이미지 장애는 좋은 기사를 탈락시키기도 한다

최근 12편 생성 배경은 단순히 디자인 취향의 문제가 아니다.
10월 9일 돈과 관련된 카드사 할인 후보가 unmapped 이미지 실패로 탈락한 뒤,
러시아 폭격·사망 기사가 Economy에 발행됐다.
10월 8일 배우 인센티브 정치 논쟁에는 교통 자산 transit-02가 쓰였다.
이미지 매핑·재고가 최종 주제 믹스를 바꾸고 있다.

그래서 “웹 사진은 성과가 좋고 생성 배경은 나쁘다”라는 단순 결론을 내리지 않는다.
역사 전체에서는 웹 이미지가 높지만 시기·주제·표지·전략이 동시에 달랐다.
먼저 매핑과 검수 경로를 복구한 뒤 비슷한 시기·주제·형식으로 다시 비교해야 한다.
현장 사진을 확보하지 못하면 무관 사진 대신 정확한 사물 그래픽이나 검수된 소유 자산을 쓴다.
현재 금지된 임의 타이포그래피 폴백을 긴급 우회로로 켜지 않는다.

Groq 공식 문서는 qwen/qwen3.8-27b의 이미지 입력 지원을 안내한다.
그러나 문서에 있는 모델과 프로젝트 계정에서 실제로 호출되는 모델은 별도 확인해야 한다.

### 5.4 정상 계정 UI와 API 오류를 혼동하지 않는다

현재 UI에는 제한이 없지만 API 오류 원인은 아직 확정하지 못했다.
HTTP 400은 다양한 원인에 쓰이며, 원장 문자열만으로 특정 error_subcode를 식별할 수 없다.
Meta 공식 문서의 제한 계정 오류와 스팸 의심 오류도 별도 코드다.
원본 code·error_subcode·error_user_msg·fbtrace_id를 비밀값 없이 기록하고,
토큰 범위·연결 계정·마지막 성공·컨테이너 상태를 확인하는 순서가 필요하다.
[Meta 공식 발행 오류 코드](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/error-codes)

현재의 정상 UI는 “섀도밴 확정” 가설을 지지하지 않는다.
그렇다고 Graph API 발행이 정상이라는 보증도 아니다.
계정 접근 오류를 일반 일시 장애처럼 계속 재시도하지 않고 운영 확인 단계로 분류하는
최소 수정이 필요하다. 인사이트 수집은 발행 재시도와 분리한다.

### 5.5 보고서의 ‘ready/complete’는 성공과 다르다

원격 performance의 ready는 v2 학습 표본이 있다는 뜻이다.
Basic complete는 4편 발행과 4편 관측이 끝났다는 뜻이며 성장 효과를 입증하지 않는다.
재계산한 v3 보고서에는 새 전략 정시 표본이 없으므로 insufficient_data가 정상이다.

기존 Slack 주간 요약은 최신 7d·72h·24h 중 하나를 게시물마다 고르고
“7일 도달”로 표시할 수 있다. 별도 Basic 보고서에도 늦은 백필 검사가 빠진 경로가 있다.
이 요약을 동일 창 실험의 근거로 쓰면 안 된다.
이번 상세 분석은 원장 raw 지표에서 창을 분리하고 Basic도 별도로 계산했다.
과거 영상의 실제 길이가 기록되지 않은 표본은 시청 비율 비교에 사용하지 않았다.

- **뉴스를 이해하는 데 어떤 배경이 필요한가:** 어려운 용어보다 실제 상황에서 출발하는 설명.

현재 증거로 알 수 없는 것은 실제 반응자의 연령·직업·금융 경험이다.
“2030 전체가 이런 걸 좋아한다”로 일반화하지 않는다.
첫 4주 동안 댓글·Story 질문에서 드러난 실제 관심을 익명 범주로 기록해 보완한다.

좋은 성과를 재현할 때 가져올 것은 큰 숫자나 자극적인 표현이 아니라
독자와의 직접 관계, 구체적인 사건, 전달할 이유다.

### 실제 벤치마킹 절차

채널별 최근 접근 가능한 콘텐츠 10개를 날짜순으로 고른다.
인기작만 모으면 실패 사례가 사라지므로, 같은 기간의 보통 콘텐츠도 기록한다.
Instagram 개별 릴스 접근이 안 되는 채널은 공식 기사 구조 참고로 표시하고
YouTube 데이터와 한 표에서 성과 순위를 매기지 않는다.

기록할 항목은 게시일·플랫폼·형식·길이·독자 상황·첫 문장·첫 답·설명 순서·마지막 행동이다.
공개 조회·좋아요·댓글에는 관찰 시각과 게시 후 경과를 붙인다.
비공개 저장·공유·팔로우·유료 광고 여부는 추정하지 않는다.

그다음 DIEM 원고에 “가져온 원리” 한 줄을 남긴다.
예: “독자의 실제 상황을 먼저 제시했다”, “가장 필요한 답을 첫 장에 넣었다”.
문구·사진·방송 화면·다른 사람의 차트를 가져오는 방식은 사용하지 않는다.
출처 링크가 있다는 것과 이미지 이용권이 있다는 것은 별개다.

## 8. 어떤 콘텐츠를 만들 것인가

기존 미션인 경제 초보 직장인을 유지한다.
새로운 종합 정치·사건 채널로 확장하기 전에 돈·생활·일자리와의 관계가 선명한 콘텐츠를 늘린다.
Economy·Issue 분리와 분야별 하루 1편 상한은 유지하되, 상한을 채우는 목표로 삼지 않는다.

초기 편집 재고의 목표는 생활 관련 뉴스 60~70%, 기초·비교 20~30%,
다시 볼 요약 10% 정도다. 이는 **다음 실험을 위한 제안 비중**이며 현재 설정을 바꾼 것은 아니다.
약한 뉴스를 줄이고 뉴스 4~6편과 Basic 1편을 공급해 주간 총 5~7편 정도로 시작한다.
주간 요약은 처음에는 Story·하이라이트로 묶어 별도 피드 물량을 늘리지 않는다.

| 콘텐츠 목적 | 독자의 질문 | 구성 | 주로 볼 지표 |
| --- | --- | --- | --- |
| 발견 | 내 돈과 생활에 무슨 변화가 있나 | 주체·변화·조건 한 가지 | 비팔로워 도달, 24h 도달 |
| 이해 | 그래서 왜 달라지는 건가 | 직접 답→이유 하나→범위·예외 | 평균 시청, 구간별 유지 |
| 저장 | 나중에 무엇을 다시 확인해야 하나 | 비교표·조건·기준일·출처 | 저장/도달, 저장 발생 편수 |
| 공유 | 누구에게 알려주면 도움이 되나 | 대상·위험·확인할 공식 경로 | 공유/도달, 실제 공유 수 |
| 반복 방문 | 이 계정을 다음에도 볼 이유는 무엇인가 | 이어지는 기초·주간 선별·업데이트 | 프로필 방문, 계정 팔로워 순증 |

한 편에서 모든 목적을 다 해결하려 하지 않는다.
먼저 그 편의 가장 중요한 목적 하나를 적고, 필요한 조건과 출처를 지킨다.

## 9. 제목·첫 화면·본문을 어떻게 바꿀 것인가

제목은 주체와 변화가 독립적으로 이해되게 쓴다.
2~3줄·최대 26자라는 현재 폭 계약 안에서 의미를 지우지 않는다.
긴 수치 설명은 검증된 사실 한 줄로 나누고 실제 렌더 너비를 검사한다.

| 현재 방식 | 문제 | 수정 방향 |
| --- | --- | --- |
| 트럼프 / 관세 발언 | 무엇을 말했는지 없음 | 기사에 실제로 나온 조건·행동을 남긴다 |
| 코인세 시행 / 반발 확대 | 확정·논의 상태와 대상 없음 | 시행 상태를 원문·공식 자료로 먼저 고정한다 |
| 청년 45% 미신청 | 비율 분모가 바뀜 | “미신청 가구 중 / 20대 이하 45%”처럼 분모 보존 |
| 주담대 금리 / 9개월 만에 최고 | 기간 손실 | “3년 9개월”을 온전히 남기거나 기간 훅을 뺀다 |
| ETF·ETN / 핵심 차이 | 답이 없고 교과서 제목 | 법적 구조의 차이 한 가지를 첫 화면에서 답한다 |
| 실온 밥 / 20대간·신장손상 | 붙여쓴 제목·조건 모호 | 나이·사례 범위를 분명히 하고 의료 해석을 넓히지 않는다 |

수정 방향은 이미 발행된 사실을 승인한 완성 제목이 아니다.
정책·건강·법적 결과의 제목은 원문과 공식 자료 대조가 선행돼야 한다.
사진이나 작은 자막을 빼고 제목만 봐도 의미가 같아야 한다.

flash의 실험안은 “큰 제목 + 답이 있는 핵심 사실 1줄”이다.
화면 설명을 길게 늘리지 않고, 캡션에는 3문장 근거·조건·출처를 보존한다.
설명을 더 담아야 하는 기사는 gate가 충족된 explain 또는 별도 검수 교육 포맷으로 보낸다.
무조건 6초에 우겨 넣지 않는다.

Basic은 첫 장에서 답의 일부를 얻도록 한다.
다음 장은 그 답의 작동 방식, 그다음은 조건·예외, 마지막은 짧은 정리로 이어진다.
“오늘의 질문”, “공통점부터” 같은 안내보다 정보 자체를 먼저 보여준다.
하나의 장에 주장 하나를 담고 자연스러운 해요체를 사용한다.

비용 0원·권리·정확성 제약 안에서도 직접 만든 간단한 비교표·수치 그래픽은 가능하다.
새 유료 서비스나 복잡한 모션 시스템을 먼저 도입할 필요는 없다.
표·도형은 질문을 설명하는 역할이 있어야 하며 장식만 늘리지 않는다.

자체 제작 설명 그래픽과 활용 가이드도 원본 콘텐츠가 될 수 있다.
자동화 자체가 비원본 제재의 원인이라는 증거는 없다.
다른 사람의 콘텐츠에 캡션·테두리만 바꾸는 방식은 피한다.

## 10. 실험 설계: 무엇이 효과였는지 알 수 있게 한다

정확성·계정 접근·측정 복구는 성장 실험과 별도로 먼저 처리한다.
오류를 일부러 남긴 대조군을 만들지 않는다.
복구 배포일 이후를 새 기준선 시작일로 기록한다.

| 실험 | 한 번에 바꿀 것 | 유지할 것 | 최소 관측 | 확대 기준 |
| --- | --- | --- | --- | --- |
| E0 운영 복구 | 배포·Vision·측정 오류 수정 | 분야·상한·음악·안전 gate | 최초 3일 + 다음 10편 | 사고 0, 핵심 지표 수집 정상 |
| E1 flash 설명 | 첫 화면에 핵심 사실 1줄 | 6초·이미지 정책·발행 시각·주제 범주 | 각 안 10편 정시 24h, 가능하면 20편 | 도달 중앙값·시청 함께 개선, 효용 악화 없음 |
| E2 Basic 순서 | 답을 첫 장으로 이동 | 5장·19초·학습 목표·조건 | 수정 4편, 이후 4편 추가 | 초기 시청·저장 개선이 2개 이상 주제에서 반복 |
| E3 이미지 문맥 | 정상 검수 사진과 매칭 그래픽 | 주제·제목·형식·비슷한 발행 기간 | 각 안 10편 목표 | 한 바이럴 제외 후에도 반복 개선 |
| E4 프로필 동선 | 고정 3개·소개·하이라이트 적용 | 같은 기간의 핵심 콘텐츠 전략 | 2~4주 계정 관측 | 프로필 방문·계정 순증 동반 개선 |
| E5 explain canary | gate 통과한 장면 설명 | 3일 간격·분야별 5편 상한 | 승인된 5편 + 필요시 다음 검토 | 장면 의미 사고 0·읽기 가능·시청 개선 |

표본 10편은 운영상 최소선이며 인과관계를 통계적으로 확정하는 숫자가 아니다.
주간 뉴스 4~6편이면 분야별 10편 또는 실험안별 10편이 모이는 데 4~6주 이상 걸릴 수 있다.
달력보다 표본을 우선하고, 분야별 비교 표본이 부족하면 그 결과는 판단 불가로 남긴다.
편집 실험은 같은 기사를 중복 발행하지 않고, 비슷한 주제·분야의 서로 다른 사건을 교차 배정한다.
완벽한 A/B 시험이 아니므로 게시 시기·주제 차이를 결과에 적는다.
품질 보호는 카테고리 10편·특성 5편이라는 v3 하한을 지킨다.
Basic 4편 재시험은 방향 판단용이며 자동 성과 prior를 학습시킬 충분한 표본이 아니다.

예산을 채우기 위해 약한 후보를 넣지 않는다.
설명·이미지·제목·길이·음악·시각을 동시에 바꾸지 않는다.
같은 주제 몇 편에서 첫 화면 설명이 좋아졌는지 확인한 뒤 다음 변수로 넘어간다.
이번에는 전면 리브랜딩이나 트렌드 음원 추가가 우선순위가 아니다.

## 11. 현실적인 목표

아래는 계정의 현재 규모와 기준선에 맞춘 **운영 목표**다.
성장 예측이나 달성 보장이 아니다. 운영 복구일을 D0로 놓는다.
분야별 표본이 부족하면 목표 실패 대신 아직 판단 불가로 기록한다.

| 시점 | 핵심 목표 | 목표를 읽는 방법 |
| --- | --- | --- |
| D0~D3 | 배포 SHA 일치, 접근 오류 원인 분리, 제목 오류 차단, Vision 검수 성공 | 성장보다 운영 정상화를 증명 |
| D14 | 정시 24h 뉴스 전체 10편, 분야별 최소 5편에서 도달 200 방향 확인 | 현재 약 138에서 약 1.45배; 정식 판정은 분야별 10편부터 |
| D28 | 분야별 도달 중앙값 300, 저장·공유 발생 20% 이상/뉴스 20편 이상, 품질 사고 0 | 점검일; 분야별 10편이 안 모이면 정식 판정 연장 |
| D28 Basic | 수정 4편 제작·발행, 성숙한 24h에서 시청 2초 방향·효용 확인 | 최종 7d 평가는 마지막 발행 +7일, 교육 수요 확정 아님 |
| D28 전환 | 30일 프로필 방문 60→90~120, 14일 계정 팔로워 순증 양수 | 서로 다른 분모·창을 섞어 전환율로 계산하지 않음 |
| D56 | 도달 중앙값 400~500, 최소 20편/분야, 효용 발생 30%, 반복 시리즈 2개 | 4주 목표 충족 뒤 확대; 표본 부족이면 판정 연장 |
| D90 | 도달 중앙값 500 유지, 800은 도전 목표, 품질 사고 0, 제작 부담 지속 가능 | 한 건 10만 조회보다 보통 콘텐츠의 개선 |

팔로워 334에서 30일 +10~25명, 60일 누적 +30~60명, 90일 누적 +60~120명을
관리 목표로 둘 수 있다. 이는 시장 평균에서 계산한 전망이 아니다.
90일 약 394~454명 규모라도 도달·저장·공유·프로필 유입이 함께 개선되면 의미 있는 회복이다.
초기에 팔로워 1,000명이나 매번 1만 조회를 성공 기준으로 잡지 않는다.
14일 순증 +1은 최소 신호이고, 그 한 항목만으로 성공이라 하지 않는다.

도달 300을 넘었는데 저장·공유가 계속 없으면 편집 효용을 바꾼다.
저장·공유가 늘었는데 도달이 낮으면 첫 화면·추천 유입·초기 유지 문제를 점검한다.
도달은 회복됐는데 프로필 방문이 작으면 어떤 다음 가치를 기대할지 안내를 개선한다.
프로필 방문이 늘었는데 계정 순증이 없으면 대표 콘텐츠와 소개의 약속이 맞는지 본다.

## 12. 90일 로드맵과 필요한 시간

### D0~D3: 잘못 돌아가는 부분부터 복구

운영 SHA·API 오류·모델 존재·제목 의미·측정 정의를 정리한다.
원격 원장을 보존한 상태로 로컬 v3를 통합·검증하는 배포 준비를 한다.
고위험 숫자 제목은 원문 대조를 필수로 하고 오류 2개를 regression fixture로 남긴다.
배포 자체는 별도 실행 작업이며 이 분석에서 수행한 것은 아니다.

### 1~2주: 콘텐츠를 적게, 정확하게, 읽히게

상위 후보를 독자 상황 기준으로 검수하고 최종 후보 외 탈락 이유도 기록한다.
같은 시간·형식에서 flash 핵심 사실 1줄 실험을 시작한다.
프로필 고정 콘텐츠 3개는 기존 자산과 최근 검수 콘텐츠를 사용해 실제 적용한다.
Basic 2~4편을 다시 준비하되 첫 장에서 답을 얻는 순서를 택한다.

### 3~4주: 도달·효용·전환을 함께 판단

분야별 10편 이상에서 정시 24h 중앙값과 72h 보조값을 본다.
수정 Basic 4편을 제작·발행하고 성숙한 24h부터 관찰한다.
최종 7d 비교는 마지막 발행일에서 7일 뒤에 한다.
부진해도 학습 목표를 버리기 전에 도입부를 다시 검토한다.
첫 한 줄 실험에서 반복 개선이 없으면 색·음악보다 질문과 소재를 수정한다.
아직 explain gate가 안 열렸으면 flash와 검수 교육 콘텐츠 안에서 계속 개선한다.

### 5~8주: 이긴 원리만 늘린다

생활 금융·주거·금리·상품 구조에서 반복 반응한 2개 시리즈를 고른다.
유형별로 준비된 패키지 2~4주치 재고를 유지한다.
좋은 반응 주제의 후속은 원문 변화가 있을 때만 만들고 같은 사건을 재포장하지 않는다.
이미지 문맥 실험은 검수 경로가 안정된 뒤 시작한다.

### 9~12주: 지속 여부 결정

도달 중앙값·효용·계정 순증·제작 시간·품질 사고를 함께 평가한다.
목표가 계속 미달이면 더 많은 자동 포스트를 만들기보다 뉴스 수를 줄이고,
독자 상황이 분명한 주간 편집과 저장형 설명에 자원을 옮기는 제한된 다음 실험을 정의한다.
새 방향으로 큰 변경이 필요하면 mission/spec을 갱신한 뒤 구현한다.

처음 2주 운영 부담은 대략 주 5일 하루 20~30분 원문·제목·최종 프레임 검수,
주 60~90분 성과 리뷰, Basic 1편당 60~120분을 예상한다.
초기 기술 복구 시간은 별도다. 주 4~6시간을 편집에 투입하기 어렵다면
발행량을 더 줄이고 주간 단위 검수 재고를 만든다.
무료 인프라가 사람의 검수 비용까지 0으로 만들어 주는 것은 아니다.

## 13. 운영 기록을 이렇게 남긴다

게시물 한 편의 기록에는 publicationKey·실제 media ID·permalink·발행일 KST·
format·영상 길이·전략 버전·독자 질문·주제·검증된 핵심 claim·이미지 주제·실험군을 넣는다.
측정에는 collectedAt·window·timingStatus·metric availability를 함께 남긴다.

계정 기록은 팔로워 총수·구간 시작/끝·프로필 방문·추천 자격·기능 제한을 별도로 둔다.
게시물별 followerDeltaEstimate를 합산하지 않는다.
저장률은 저장/reach, 공유율은 공유/reach로 계산하고 같은 창끼리만 비교한다.
게시물 reach 합계는 여러 게시물을 중복해서 본 계정을 포함하므로 계정 고유 도달이라고 부르지 않는다.
누락 지표는 unavailable로 남긴다.

후보 기록에는 “독자에게 좋은데 이미지에서 실패한 후보”와
“편집·분류·제목에서 실패한 후보”를 구분한다.
품질 gate 실패 수·실제 발행 사고 수·수동 삭제·정정 수는 다른 항목으로 관리한다.
Action 성공 표시만으로 정상 발행이나 무사고라고 하지 않는다.

벤치마크 기록에는 관찰일·공식 URL·플랫폼·게시 경과·공개 지표·배울 원리·
DIEM에 적용한 변경·복사하지 않은 요소·결과를 넣는다.
성과 우위가 확인되지 않은 채널은 구조 참고라고 표시한다.

## 14. 이번에 하지 말아야 할 조치

- 낮은 조회수만 보고 계정 삭제·새 계정 개설·전체 게시물 삭제.
- 사례 하나를 보고 세금·정치·부동산만 대량 발행.
- 확인되지 않은 얼굴·방송 화면·무관 사진을 써서 현장성을 흉내 내기.
- 모델 오류를 무시하고 Vision 또는 사실 검증 gate를 우회.
- 신규 v3 성과로 과거 원장을 소급 변환해 학습 prior를 켜기.
- 설명을 끝내기 전에 큰 팔로우 문구를 반복.
- 유료 광고로 기본 콘텐츠 효용이 회복됐다고 판정.
- 색·음악·제목·길이·빈도를 한 번에 바꾸고 원인을 추정.

## 15. 분석에서 남은 불확실성과 검증

비팔로워 비중·실제 3초 유지·완주·릴스별 팔로우·유입 경로·광고 여부는
확보하지 못했다. 최근 도달 하락의 개별 원인 기여도와 인과 효과도 확정하지 못했다.
현재 UI의 추천 자격 정상은 과거 상태와 API 정상 작동을 모두 보증하지 않는다.
API 오류 원인은 raw subcode가 없어 미확정이다.

외부 Instagram 개별 게시물 지표의 접근 제한 때문에 어피티·뉴닉을
“현재 DIEM보다 릴스가 몇 배 잘된다”라고 쓰지 않았다.
YouTube 사례의 성공 규모는 공식 공개 화면에서 확인했지만 플랫폼·길이·게시 연령이 다르다.

현재 프로필에서는 예정된 고정 3개와 하이라이트 구성이 적용되지 않은 것을 확인했다.
Basic 4편 이후 후속 발행과 cloud-assisted 실뉴스 package 성공 증거는 원격 기록에 없었다.
연결 canary 성공과 실제 콘텐츠 운영 성공을 구분해야 한다.

프로젝트 검증은 harness의 npm run test와 git diff --check를 실행했다.
테스트 406개 중 403개 통과·3개 skip·실패 0이었다.
이는 로컬 코드 검증이며 실제 API 발행·새 Vision 검수·개선 전략의 성장 효과를 증명하지 않는다.
이번 변경은 분석 보고서·체크리스트·증거 자료와 성과 보고서 갱신이다.
production 코드·설정·스케줄·게시물을 변경하지 않았다.
