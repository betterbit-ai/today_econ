# 애매한 인기 후보는 제한된 원문 확인 뒤 최종 분류한다

## Decision

뉴스 현장의 축약어와 동의어를 결정적으로 표준화하고, 제목·목록 요약만으로
허용 분야를 확정할 수 없는 통합 인기 상위 25개 후보는 원문을 확보한 뒤
제목·요약·본문 도입부로 재분류한다. 최초 분류와 원문 확인 판단, 최종
분류를 후보별 실행 기록에 보존한다.

## Context and constraints

`마통`·`주담대`, `KTX`·`SRT`, `폭염`·`중대본`처럼 독자에게 유의미한
기사들이 기존 제목 키워드 허용 목록에 없다는 이유로 원문 확인 전에
`category_not_allowed`가 됐다. 반면 모든 후보 원문을 매 실행마다 읽으면
4시간 주기의 두 워크플로에서 외부 요청 수와 실행 시간이 불필요하게
늘어난다. 분야 판정은 발행 신뢰 경계이므로 무료 LLM의 가용성이나 변동성에
의존해서도 안 된다.

상위 25건은 50건 순위를 1~100으로 정규화했을 때 일일 최소 발행의 인기
하한인 약 50점 이상 후보를 포괄한다. 명시적 제외 후보는 조회하지 않아
비용을 아끼고, 나머지 애매한 후보만 이 범위에서 원문으로 구제한다.

## Alternatives considered

- 키워드 정규식만 계속 확장: 알려진 사례는 고치지만 다음 축약어와 제목
  생략 사례에서 같은 조기 탈락이 반복되어 거절했다.
- 모든 후보를 LLM으로 분류: 무료 API 한도, 재현성, 장애 시 전체 선정 중단
  위험 때문에 거절했다.
- 모든 후보 원문을 조회: 누락 가능성은 낮지만 두 분야가 4시간마다 실행되는
  현재 규모에서 과도한 네트워크 비용과 지연을 만들기 때문에 거절했다.

## Revisit when

- 인기 공급자의 후보 수나 점수 분포가 바뀌어 상위 25건이 일일 최소 인기
  하한을 더 이상 포괄하지 않을 때
- 원문 요청 실패율 또는 실행 시간이 운영 목표를 넘을 때
- 실제 분류 추적에서 상위 25건 밖의 유의미한 후보 누락이 반복 확인될 때
