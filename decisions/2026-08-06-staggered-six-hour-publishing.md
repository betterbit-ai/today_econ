# 카테고리별 발행 기회를 6시간 주기로 엇갈리게 배치한다

## Decision

`DIEM Economy`와 `DIEM Issue`는 독립 발행 액션과 schema v3 Git 원장,
당일 사건 중복 차단, 미완료 실행 우선 복구 구조를 유지한다. 다만 자동
실행 기회는 분야별 하루 6회에서 4회로 줄인다. Economy는 KST
01·07·13·19시, Issue는 KST 04·10·16·22시에 실행해 분야 사이를 3시간
간격으로 벌린다.

이에 따라 전체 자동 평가 기회는 하루 12회에서 8회로 66.7%가 된다.
핫뉴스의 인기·신선도·편집 가치 기준은 발행량을 맞추기 위해 낮추거나
높이지 않는다. 마지막 성공 Reel 이후 다음 6시간 실행 전에 24시간
공백이 생기지 않도록 Economy의 일일 최소 발행 평가는 18시간부터
시작한다. 24시간 무발행 경보와 품질·사실·중복·이미지 가드는 유지한다.

## Context and constraints

Git 원장상 실제 Reel 발행량은 8월 1일부터 6일까지 일별 2·4·5·8·10·7편으로
증가했다. 두 액션이 같은 4시간 cron을 사용해 서로 다른 분야의 Reel이
수십 분 안에 연속 게시되기도 했다. 사용자가 원하는 현재 대비 약 65%의
빈도에 가장 가까운 단순하고 검증 가능한 조정은 실행 기회를 12회에서
8회로 줄이는 것이다.

DIEM은 중요한 핫뉴스를 놓치지 않아야 하므로 편집 점수나 신선도 임계값을
발행량 조절 장치로 사용하지 않는다. 별도 DB·상시 서버·유료 스케줄러도
도입하지 않는다. 수동 `workflow_dispatch`는 횟수 제한 없이 유지한다.

## Alternatives considered

- 분야별 하루 3편의 하드 캡: 긴급 속보도 막을 수 있고 수동 발행과 자동
  발행의 경계를 추가로 관리해야 해 기각했다.
- 기존 4시간 실행을 유지하고 핫 점수만 상향: 편집 가치의 의미를 운영
  빈도에 따라 흔들고 기사 유형별 편향을 키우므로 기각했다.
- 두 분야를 같은 6시간 시각에 실행: 총량은 줄지만 연속 발행 문제는 남아
  3시간 교차 실행으로 대체했다.

## Revisit when

- 14일 운영 데이터에서 실제 발행량이 목표 범위보다 계속 높거나 낮을 때
- 6시간 사이에 놓친 시간 민감 뉴스가 반복될 때
- Instagram 도달·팔로우 전환 데이터로 분야별 최적 시간대를 판단할 수 있을 때
- 하루 24시간 무발행 방지 기준이나 수동 발행 정책을 바꿀 때
