# 자동 발행을 유지하면서 복구와 콘텐츠 실험을 분리한다

## Decision

운영 복구를 먼저 배포하고 실제 예약 발행으로 확인한 후 첫 화면 실험과 Basic 재시험을 순서대로 시작한다.

## Context and constraints

계정 UI의 정상 상태는 발행 API 접근 성공을 증명하지 않는다. 이미지 매핑 실패와 Vision 모델 접근 실패도 콘텐츠 수요 감소와 구분해야 한다. 자동 발행, 기존 예약 시각, 분야별 하루 한 편 상한, 무료 인프라와 기존 의존성을 유지한다. 적합한 후보가 없으면 발행하지 않는다.

기존 원장과 최초 관측은 소급 수정하지 않는다. 오류 문자열에 비밀값을 제거한 구조화 근거를 추가하고, 재수집 관측은 별도로 보존한다. 정시 창과 콘텐츠 유형을 구분한 관측만 성과 판단에 사용한다. 읽기 진단은 계정 조회와 실제 이미지 검수만 수행하며 게시물을 만들지 않는다.

## Alternatives considered

- 매일 사람 승인: 사용자가 선택한 자동 운영과 맞지 않는다.
- 복구와 표지·음악·발행 시각 실험을 동시에 배포: 복구 효과와 콘텐츠 효과를 분리할 수 없다.
- 무관 자산으로 발행량 채우기: 실제 사건을 오해하게 만드는 품질 사고를 재현한다.
- 늦게 받은 누적값으로 정시 관측 덮어쓰기: 비교 창이 조용히 바뀐다.

## Revisit when

main SHA, 실행 SHA, 새 analytics schema3, 정상 실제 발행 결과가 연결되면 다음 변경 묶음으로 진행한다. 이미지 진단 성공은 explain 분류·초안 증거를 대신하지 않는다. 제한·인증 오류가 지속되면 해당 계정 소유자의 정상 인증 절차를 운영 확인 대상으로 남긴다.
