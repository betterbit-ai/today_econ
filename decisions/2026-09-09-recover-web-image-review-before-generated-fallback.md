# 생성 폴백 전에 웹 이미지 검수 장애를 제한적으로 복구한다

## Decision

웹 이미지 후보가 있는 상태에서 Groq Vision의 JSON 모드 또는 원격 URL
접근만 실패한 경우를 이미지 부적합으로 취급하지 않는다. JSON 모드는 형식
강제를 해제해 한 번 재요청하고, 401·403 URL 장애는 이미지를 로컬에서 받아
Base64로 한 번 재검수한다. 이미지당 8MB, 다운로드 15초, 기사당 서로 다른
검수 의도 3회로 제한한다.

기술 복구 뒤에도 실제 픽셀 검수를 통과한 웹 이미지만 발행한다. 모든 검수가
실패하면 기존처럼 검수된 프로젝트 생성 자산으로 닫되, 생성 주제는 잠긴
news frame의 주체·사건을 사용한다. 부수적인 직업·기업 이력·본문 후반 단어는
이미지 주제를 바꾸지 못한다.

## Context

2026-09-01~08 발행 26편 중 웹 이미지는 0편이었다. 23편에 Vision 실패가
기록됐고 그중 19편은 `json_validate_failed`, 3편은 원격 이미지 403이었다.
검색 공급원이 후보를 찾지 못한 것이 아니라 검수 전송 계층의 장애가 모든
후보를 생성 폴백으로 밀어냈다.

## Rejected

- Vision 장애 시 메타데이터 1위 웹 이미지를 그대로 발행: 무관 인물·국가·
  정치 상징 사고를 재발시켜 채택하지 않았다.
- 무제한 검색·재시도: 무료 티어와 실행 시간을 소진하므로 채택하지 않았다.
- 생성 폴백을 완전히 제거: 권리와 실제 픽셀 검수를 통과할 웹 사진이 없는
  정상적인 경우가 있어 채택하지 않았다.

## Directive

검수 장애 복구는 웹 이미지 안전 게이트를 우회하는 기능이 아니다. 복구 응답도
관련성·국가·정치 상징·무관 인물 검사를 모두 통과해야 한다.
