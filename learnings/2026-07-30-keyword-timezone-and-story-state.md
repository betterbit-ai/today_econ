# 분야 단어·서버 시간·비영속 후처리는 실제 발행 품질을 보장하지 못한다

## Situation

태국 학생의 분장 관련 병원 이송 단신이 `학생`, `의료`, `긴급` 단어 때문에
공익성이 높은 최신 시사 기사로 발행됐다. 공급자 사진도 `healthcare`만
일치하는 성인 의료인 사진이 선택돼 기사 속 학생·환자와 다른 인상을 줬다.
같은 날 산업 기사 제목은 중국이 배터리·조선에서 이미 앞선다는 원문을
`중국 추격`으로 뒤집어 읽히게 했다.

Story는 과거 코드에 게시 호출이 있었지만 GitHub Actions가 환경 변수로
기능을 끄고 있었다. 실패를 원장에 저장하지 않고 한 프로세스에서만 세 번
재시도해 다음 실행이 미완료 Story를 알 수도 없었다.

## What we learned

- 분야 단어는 분류 신호일 뿐 공익성 증거가 아니다. 한 개인의 기이한 사건은
  정책·제도·다수 영향이 없으면 의료·교육 단어가 있어도 시사 뉴스가 아니다.
- `YYYY-MM-DD HH:mm:ss`를 UTC 러너의 로컬 시간으로 파싱하면 국내 기사 시각이
  9시간 최신으로 부풀려질 수 있다. 발행처 계약에 맞춰 Asia/Seoul을 명시해야
  한다.
- `긴급 이송`의 긴급과 `긴급 정책 결정`의 긴급은 다르다. 단어 하나가 아니라
  사건 유형까지 묶어 긴급성 보너스를 줘야 한다.
- 이미지 주제 일치에는 장소·업종뿐 아니라 인물의 역할·연령·사건 속 지위가
  포함된다. 환자 기사에 의사 사진을 쓰는 것은 의미 일치가 아니라 역할 충돌이다.
- 제목 검증은 숫자와 주장 상태만으로 부족하다. 경쟁·증감·전환 기사는 주체와
  방향을 구조화하지 않으면 짧은 축약이 사실관계를 뒤집을 수 있다.
- 외부 발행 후처리는 릴스와 같은 영속 상태 모델을 가져야 한다. 메모리 안에서
  재시도한 결과는 다음 GitHub Actions 실행에서 복구할 수 없다.
- Story의 `media_publish`가 성공한 뒤 선택적 메타데이터 조회가 실패해도 게시
  자체는 성공이다. 이 후속 조회 오류를 전체 실패로 처리하면 Story가 중복될 수
  있다.

## Next time

- 실제 실패 기사를 후보 평가부터 표지·본문·배포까지 잇는 회귀 fixture로 남긴다.
- 시간대 없는 국내 게시 시각은 KST로 파싱하고 미래 시각은 관측 시각 폴백으로
  명시적으로 기록한다.
- 이미지 메타데이터에서 기사 시각 역할이 확인되지 않으면 무사진 표지를 택한다.
- 선두·추격·전환 기사는 뉴스 프레임과 제목 방향 검증을 함께 추가한다.
- Reel, Story, 댓글의 성공·실패·시도 횟수를 각각 Git 원장에 저장하고, 새 후보
  선정보다 미완료 외부 단계를 먼저 복구한다.
